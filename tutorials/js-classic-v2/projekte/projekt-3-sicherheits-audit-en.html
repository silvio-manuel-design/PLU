Security Audit

You get insecure code and find the holes. Then you close them. Time: about 120 min.

Your task

The task below contains a page with four security holes. Find every hole and describe it in two sentences. Then write a corrected version. Your report and the file both belong to the submission.

Read the code twice before you start — half the holes only show on the second read.

Allowed tools

Allowed

  • Everything from chapters 01–12 — you hardly need new code, mostly sharp eyes.

Not allowed

  • Taking over another student's solution.

Design

Guidelines

  • Your corrected file looks like the original — only safer.
  • The audit report sits as an HTML comment at the top of the file.
  • Test with the XSS input from step 5 before you submit.

Requirements

Find all four holes and describe each in two sentences. Only check a line when your code or report really does it.

Step by step

  1. 1

    Read and note

    Read the insecure code twice. Note suspicious spots before you judge.

  2. 2

    Four holes

    Find all four holes. Describe each in two sentences — in your own words.

  3. 3

    Create the file

    Create project-3-security-audit.html. Put your report as an HTML comment at the top of the file.

  4. 4

    Fix it

    Rewrite the page: textContent instead of innerHTML, addEventListener instead of onclick. Remove eval completely and replace var with let or const.

  5. 5

    XSS test

    Test the guestbook with an input like <img src=x onerror=alert(1)>. Nothing must execute.

  6. 6

    Polish

    Have AI review your solution. Check its criticism yourself, then check off all requirements.

Work with AI

Rule: AI finds holes fast. Your report must still carry your own words.

Starter prompt — copy it and fill in your details:

Three check questions

  • Why is innerHTML with user input dangerous?
  • What makes eval so risky?
  • Why is addEventListener cleaner than onclick?

Submission
