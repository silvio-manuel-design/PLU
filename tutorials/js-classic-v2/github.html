GitHub & Abgabe

Deine Arbeit sicher speichern, versionieren und abgeben — mit dem Werkzeug echter Entwickler und dem Template deiner Klasse. Alles mit Standard-GitHub, ganz ohne Zusatz-Tools.

Zu GitHub (externer Link, öffnet neues Fenster)

ERST MAL VERSTEHEN

Du kennst das: referat.docx, referat_final.docx, referat_ECHTfinal.docx. Am Ende weißt du nicht mehr, welche Version die neueste ist.

Git beendet dieses Chaos. Jeder Stand deiner Arbeit bekommt einen Namen und ein Datum. Du kannst jederzeit zurück. Du kannst von jedem Gerät weiterarbeiten. Und deine Lehrkraft sieht deine Arbeit — ohne dass du etwas hochladen musst.

Für Schüler: Erste Abgabe einrichten

  1. 1

    GitHub-Account prüfen

    Bevor es losgeht, zwei Kontrollen:

    • Bist du bei GitHub eingeloggt?
    • Bist du Mitglied der Klassen-Organisation? (Deine Lehrkraft lädt dich ein.)
  2. 2

    VS Code verbinden

    Drei Dinge einmalig einrichten:

    • Extensions installieren (siehe VS-Code-Seite)
    • Git installieren (git-scm.com)
    • In VS Code: Account-Menü → „Sign in with GitHub"
  3. 3

    Dein Repo aus dem Template erstellen

    Deine Lehrkraft schickt dir den Link zum Template der Klasse. Auf der Template-Seite:

    • „Use this template" → „Create a new repository"
    • Owner: deine Klassen-Organisation (im Owner-Dropdown oben auswählen, z. B. 2BFITT)
    • Name nach dem Kurs-Schema, z. B. jsc-kap04-17
    • Private → Create
    • So funktioniert's: Das Repo liegt in der Organisation deiner Klasse — du arbeitest als Mitglied darin, und deine Lehrkraft sieht es automatisch. Einen Einladungs-Schritt gibt es nicht: Wer in der Organisation ist, sieht private Repos der Org.
  4. 4

    Klonen

    Klonen heißt: Eine Kopie des Repos landet auf deinem Rechner.

    • Auf deinem Repo die grüne Schaltfläche „<> Code" → Reiter HTTPS → URL kopieren
    • In VS Code: Strg+Shift+P → „Git: Clone" → URL einfügen
    • Speicherort wählen (z. B. Dokumente → web) → „Open"
    • Kontrolle: Im Explorer links steht der Repo-Name samt Dateien — darunter die README.md aus dem Template.
  5. 5

    Arbeiten

    Jetzt geht's ans Eigentliche:

    • Dateien aus dem Explorer öffnen und Übungen lösen — genau wie auf den Kapitelseiten, nur in deinem eigenen Ordner
    • Speichern nicht vergessen (Strg+S)
    • Tipp: Zwischen den Aufgaben einmal committen (nächster Schritt) — dann ist jeder Zwischenstand gerettet, falls etwas kaputt geht.
  6. 6

    Committen

    Ein Commit ist ein beschrifteter Zwischenstand.

    • Quellcode-Panel (Strg+Shift+G): unter „Änderungen" auf + klicken
    • Oben eine Nachricht schreiben, die sagt, was du getan hast („Kap02 Übung 1 gelöst")
    • Häkchen klicken = Commit
    • Beim ersten Mal fragt VS Code nach Name und E-Mail — GitHub-Name und deine Mail eintragen, einmalig
    • Kontrolle: Die Liste „Änderungen" ist leer und dein Stand steht unter „Commits".
  7. 7

    Pushen

    Committen rettet den Stand nur lokal — pushen überträgt ihn zu GitHub.

    • Pfeil-Symbol „Sync Changes" klicken (beim ersten Mal „Publish Branch")
    • Fertig, wenn der Pfeil stillsteht
    • Kontrolle: Öffne dein Repo im Browser — dein Commit mit Zeitstempel muss dort sichtbar sein. Nur was gepusht ist, kann deine Lehrkraft sehen.
  8. 8

    Abgabe abschließen

    Fertig? Noch zwei Kleinigkeiten:

    • Deiner Lehrkraft den Repo-Namen sagen (z. B. jsc-kap04-17) — sie findet dein Repo über die Org-Suche
    • Bedenken: Abgegeben ist nur, was gepusht ist.

Typische Fehler

„Authentication failed"

Abgemeldet oder abgelaufen — in VS Code neu mit GitHub anmelden (Account-Menü → Sign in).

„Repository not found" beim Klonen

URL prüfen — und die Mitgliedschaft in der Organisation muss vorher akzeptiert sein (Mail von GitHub mit „Join").

„Commit geht nicht"

Einmalig Namen und E-Mail setzen (VS Code fragt beim ersten Commit danach) — dann läuft es.

„Ich hab ins falsche Repo gepusht"

Kein Drama: Lehrkraft fragen, Stand korrigieren, neu committen. Genau dafür ist Git da.

Für Lehrkräfte: GitHub im Unterricht einrichten

  1. 1

    Account & Organisation

    Der eigene Klassenraum auf GitHub — einmal eingerichtet, läuft er:

    • GitHub-Account anlegen — mit deiner Schul- oder privaten E-Mail-Adresse, wie es deine Schule erlaubt (oder einen vorhandenen Account nutzen)
    • Profilmenü → Organizations → New organization — kostenlos; Name z. B. htl-web-2a. Du bist damit Administratorin oder Administrator des Klassenraums
    • Schüler:innen über Username oder E-Mail einladen
    • Tipp: Schüler:innen arbeiten mit Nummern statt Klarnamen — auch bei den GitHub-Usernames
    • Wichtig (einmalig): Organization → Settings → Member privileges → „Repository creation" auf „Public and private repositories" stellen
    • Ebenfalls: den Haken bei „Repository visibility change" („Allow members to change repository visibilities") entfernen — so kann niemand aus Versehen ein privates Repo auf Public stellen.
  2. 2

    Template-Repo anlegen & pflegen

    Neues Repo in der Organisation mit den Starter-Dateien:

    • index.html, css/, js/, README.md als Arbeitsanleitung (die Aufgabenstellungen stehen im Tutorial), .gitignore
    • Repo → Settings → Haken bei „Template repository"
    • Fertig: Dieses Template ist der Grundstock jeder Abgabe — bewusst Standard-GitHub, ganz ohne Zusatz-Tools. Wenn das Template steht, brauchst du nichts weiter zu verwalten.
  3. 3

    Link verteilen & Namensschema vorgeben

    Vorbereitung, damit die erste Stunde reibungslos läuft:

    • Template-Link über den üblichen Kurskanal schicken (LMS, E-Mail, Tafelbild) — einen Tag vor der ersten Einheit, damit die Registrierung nicht in der Stunde passiert
    • Namensschema verbindlich vorgeben: jsc-kapXX-nr für die Übungen jedes Kapitels, jsc-projekt-1-nr bis jsc-projekt-3-nr für die drei Projekte, jsc-abschluss-nr für das Abschlussprojekt — eindeutig, anonym, sortierbar
    • Der Trick: Die Klasse steht nicht im Namen, sie steckt bereits in der Organisation — damit findest du jede Abgabe über die Org-Suche, auch bei 60 Repos.
  4. 4

    Erste Einheit planen

    Der Ablauf der ersten Stunde:

    • Rechnerzeit einplanen: Schüler:innen folgen der Schüler-Anleitung oben
    • Mit 20–30 Minuten für die ersten Clones und Anmeldungen rechnen — danach läuft der Workflow
    • Den Link zu dieser Seite verteilen; der Template-Link reist separat
  5. 5

    Abgaben sammeln & prüfen

    Als Eigentümer:in der Organisation siehst du alle Repos automatisch — es gibt keine Collaborator-Einladungen mehr anzunehmen.

    • Überblick per Org-Suche: jsc-kap04 zeigt alle Abgaben des Kapitels, jsc-abschluss alle Abschlussprojekte
    • Wer nicht pusht, siehst du am fehlenden Zeitstempel
    • Für die Terminal-Triage genügt git status auf dem Rechner der Person
    • Für Fortgeschrittene: gh CLI (gh search repos)
  6. 6

    Feedback geben

    Feedback direkt am Schüler-Stand:

    • Im Schüler-Repo: ein Issue oder ein Kommentar pro Commit — so bleibt das Feedback am Stand, auf den es sich bezieht
    • Keine Korrektur-Commits direkt auf main, das würde die Geschichte durcheinanderbringen.
  7. 7

    Kursmaterial aktualisieren

    Das Template ist dein lebendes Kursmaterial:

    • Ändert sich eine Aufgabenstellung, aktualisiere das Template-Repo — die nächste Klasse startet automatisch mit dem neuen Stand
    • Alte Abgaben bleiben unberührt, denn jedes Schüler-Repo ist eine eigenständige Kopie.
  8. 8

    Datenschutz-Kurzcheck

    Vier Minuten, einmal pro Kurs:

    • Private Repos
    • Keine Klarnamen in Repo-Namen und Usernames
    • Keine Noten in Repos
    • Schüler:innen-Accounts über die Schülermail
    • Reflexionen (.md) bleiben lokal auf den Geräten
    • Bei Minderjährigen: Einverständnis der Eltern für den Online-Account einholen — wie bei jedem Kurs-Tool.

Typische Fehler

„Schüler hat keinen Account"

Anmeldung mit Schülermail, GitHub Student Pack optional — in Minuten erledigt.

„Zu viele Einzel-Repos"

Namensschema + Org-Suche statt Dashboard — so behältst du auch bei 30 Repos den Überblick.

„Schüler pusht nicht"

Terminal-Triage: git status zeigt, was committet oder gepusht werden muss.

„Org-Grenzen"

Der Free-Plan reicht für private Repos im Unterrichtsmaßstab — keine Kosten, kein Upgrade nötig.
