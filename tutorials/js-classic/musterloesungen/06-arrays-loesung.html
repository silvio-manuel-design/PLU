📋 Musterlösung – Kapitel 6: Arrays

Aufgabe 1: Index-Falle

Warum undefined?

farben.length ist 3 (Array hat 3 Elemente).
Aber die Indizes sind: 0 (rot), 1 (grün), 2 (blau).
→ farben[3] existiert nicht → undefined.

Zwei korrekte Methoden:

  • Mit Index: farben[farben.length - 1]
  • Mit Methode: farben.at(-1) (modern) oder farben[farben.length - 1]

Sichere Funktion:

function gibLetztesElement(arr) {
  if (arr.length === 0) {
    return null;
  }
  return arr[arr.length - 1];
}

Möglicher Prompt:

Erstelle eine Funktion gibLetztesElement(arr), die das letzte Element eines Arrays zurückgibt.
Wenn das Array leer ist, gib null zurück.
Verwende arr.length - 1 für den Index.

Aufgabe 2: Array-Methoden

Endzustand:

  • original: ["A", "B", "C", "D"] (wurde durch kopie1 verändert!)
  • kopie1: ["A", "B", "C", "D"] (gleiche Referenz wie original)
  • kopie2: ["A", "B"] (echte Kopie – pop() wirkt nur hier)

Referenz vs. echte Kopie:

✅ kopie1 = original → beide Variablen zeigen auf **dasselbe Array im Speicher**.
✅ kopie2 = original.slice() → erzeugt ein **neues Array** mit den gleichen Werten.

Warum bei Objekten kritischer?

Bei const arr = [{ name: "A" }]; const kopie = arr.slice();
ist die **äußere Ebene** kopiert – aber die **Objekte darin** sind noch **Referenzen**!
→ Ändert man kopie[0].name, ändert sich auch arr[0].name.

Möglicher Prompt:

Erstelle eine tiefe Kopie eines flachen Arrays (nur primitive Werte wie Strings, Zahlen).
Erkläre, warum slice() bei flachen Arrays ausreicht, aber bei verschachtelten Arrays nicht.
Gib ein Beispiel für beide Fälle.
