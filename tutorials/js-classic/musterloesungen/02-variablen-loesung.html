🧮 Musterlösung – Kapitel 2: Variablen & Datentypen

Aufgabe 1: Typen-Rätsel

  • typeof a → "string"
  • typeof b → "number"
  • typeof c → "boolean"
  • typeof d → "undefined"

Warum ist typeof null === "object"?

Historischer Bug aus dem Jahr 1995: In der ersten JavaScript-Implementierung wurde der Typ-Tag für Objekte als 0 gespeichert – und null war ebenfalls 0. Der Fehler wurde nie korrigiert, um die Abwärtskompatibilität zu wahren.

Funktion konvertiereZuZahl:

function konvertiereZuZahl(wert) {
  const zahl = Number(wert);
  if (isNaN(zahl)) {
    return { erfolgreich: false, ergebnis: null };
  }
  return { erfolgreich: true, ergebnis: zahl };
}

Möglicher Prompt:

Erstelle eine Funktion konvertiereZuZahl(wert), die versucht, einen beliebigen Wert in eine Zahl umzuwandeln. 
Gib ein Objekt zurück mit "erfolgreich: true/false" und "ergebnis: Zahl oder null". 
Behandle NaN sicher mit isNaN().

Aufgabe 2: Namensgebung

SzenarioWahlNameBegründung
Tagesmenü (ändert sich) let tagesmenue Wert ändert sich täglich → let
Steuerrate (fest) const steuerrateGetraenke Konstante, gesetzlich festgelegt → const
Anzahl Kaffees let anzahlKaffees Wird inkrementiert → let
Öffnungszeiten const oeffnungszeiten Ändert sich nie → const

Häufige Fehler:

  • const wird als „konstante Zahl“ missverstanden – dabei meint es „unveränderliche Bindung“.
  • Variablennamen wie 1name oder let (Schlüsselwort) → Syntaxfehler.
  • Fehlende Aussagekraft: x, data statt anzahlKaffees.
