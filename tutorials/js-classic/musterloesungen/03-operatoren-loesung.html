⚖️ Musterlösung – Kapitel 3: Operatoren

Aufgabe 1: Gleichheit

  • 0 == false → true
    Bei == wird false zu 0 konvertiert → 0 == 0.
  • 0 === false → false
    Typen unterschiedlich (number vs boolean) → strikte Prüfung schlägt fehl.
  • null == undefined → true
    Spezialfall: Diese beiden Werte sind bei == gleich – historisch bedingt.
  • null === undefined → false
    Typen unterschiedlich (object vs undefined).
  • "5" == 5 → true
    String wird zu Zahl konvertiert → 5 == 5.
  • "5" === 5 → false
    Typen unterschiedlich (string vs number).

Meine Regel:

✅ Immer === verwenden.
❌ == nur in sehr speziellen Fällen (z. B. explizite Prüfung auf null oder undefined mit == null).

Möglicher Prompt:

Aufgabe 2: Ternärer Operator

Kann man es mit ternärem Operator lösen?

Technisch ja, aber praktisch nein. Man könnte verschachteln:

const status = (punkte >= 90) ? "Ausgezeichnet" :
                (punkte >= 75) ? "Gut" :
                (punkte >= 60) ? "Genügend" : "Nicht genügend";

Das ist aber **schwer lesbar** und **fehleranfällig**.

Warum ist if...else besser?

  • ✅ Mehrzeilig – gut lesbar
  • ✅ Jede Bedingung steht klar für sich
  • ✅ Leicht erweiterbar (z. B. Logik pro Fall hinzufügen)

Allgemeine Regel:

✅ Ternärer Operator nur bei **einfachen, einzeiligen Entscheidungen**: const farbe = istGültig ? "grün" : "rot";
❌ Nicht bei mehr als zwei Ausprägungen oder komplexer Logik.

Möglicher Prompt:
