🌐 Musterlösung – Kapitel 9: DOM-Manipulation

Aufgabe 1: innerHTML vs. textContent

Unterschied:

  • innerHTML: Interpretiert den String als HTML – führt Skripte aus!
  • textContent: Behandelt den String als reinen Text – HTML wird nicht interpretiert.

Bei bösartiger Eingabe:

  • innerHTML: Führt den <script>-Tag aus → XSS-Angriff!
  • textContent: Zeigt den Code als Text an → sicher.

Wann ist innerHTML sinnvoll?

✅ Wenn du **vertrauenswürdigen HTML-Code** einfügst – z. B. aus deinem eigenen Template:
element.innerHTML = "<p>Willkommen, " + name + "!</p>";

Möglicher Prompt:

Erstelle eine Funktion zeigeBenutzer(eingabe), die den Text sicher anzeigt.
Verwende textContent für Benutzereingaben.
Verwende innerHTML nur, wenn der Inhalt aus vertrauenswürdigem Code stammt.

Aufgabe 2: Dynamische Liste

Lösung:

function zeigeListe(elemente) {
  const ul = document.getElementById("liste");
  if (!ul) {
    console.error("Element mit ID 'liste' nicht gefunden!");
    return;
  }
  // Alten Inhalt leeren
  ul.innerHTML = "";

  // Liste im Speicher bauen
  const fragment = document.createDocumentFragment();
  for (const item of elemente) {
    const li = document.createElement("li");
    li.textContent = item;
    fragment.appendChild(li);
  }
  ul.appendChild(fragment);
}

Warum im Speicher bauen?

✅ Jeder Zugriff auf den DOM ist **langsam**.
Wenn du 100 li nacheinander einfügst, wird die Seite 100× neu gerendert.
Mit DocumentFragment wird nur **einmal** gerendert → besser für Performance.

Fehlerbehandlung:

✅ Prüfe mit if (!ul), ob das Element existiert – sonst gibt es einen Fehler.

Möglicher Prompt:

Erstelle eine Funktion zeigeListe(elemente), die eine ul-Liste mit li-Elementen füllt.
Verwende createElement und textContent.
Baue die Liste im Speicher (mit DocumentFragment) und füge sie dann einmalig ein.
Füge eine Fehlerprüfung ein, falls das Ziel-Element nicht existiert.
