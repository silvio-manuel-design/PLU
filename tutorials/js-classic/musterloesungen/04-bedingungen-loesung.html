🔀 Musterlösung – Kapitel 4: Bedingungen

Aufgabe 1: Logik-Rätsel

Lösung – Eintrittsbedingung:

if (isVip || alter >= 18 || (alter < 18 && hatErzieher)) {
  // Eintritt erlaubt
}

Testfälle:

  • alter=17, hatErzieher=true, isVip=false → erlaubt ✅
  • alter=16, hatErzieher=false, isVip=true → erlaubt ✅
  • alter=20, hatErzieher=false, isVip=false → erlaubt ✅
  • alter=15, hatErzieher=false, isVip=false → nicht erlaubt ❌

Warum Klammern?

Ohne Klammern: alter < 18 && hatErzieher wird zuerst ausgewertet (wegen Präzedenz), aber zur Klarheit **immer klammern**, wenn gemischt wird: (isVip) || (alter >= 18) || (alter < 18 && hatErzieher)

Möglicher Prompt:

Erstelle eine if-Bedingung für einen Club-Eintritt mit drei Regeln:
1. VIPs immer erlaubt,
2. ab 18 alleine erlaubt,
3. unter 18 nur mit Erziehungsberechtigtem.
Verwende logische Operatoren und setze Klammern für Klarheit.

Aufgabe 2: Fehleranalyse

Warum „Befriedigend“ bei 95 Punkten?

Der Code prüft **alle if-Blöcke nacheinander**:

  1. 95 > 90 → bewertung = "Sehr gut"
  2. 95 > 80 → bewertung = "Gut" (überschreibt!)
  3. 95 > 70 → bewertung = "Befriedigend" (überschreibt erneut!)
Der else-Block wird nicht ausgeführt, aber die vorherigen if laufen alle.

Verbesserung mit else if:

if (punkte >= 90) {
  bewertung = "Sehr gut";
} else if (punkte >= 80) {
  bewertung = "Gut";
} else if (punkte >= 70) {
  bewertung = "Befriedigend";
} else {
  bewertung = "Nicht genügend";
}

Warum else if besser ist:

✅ Nur der **erste passende Fall** wird ausgeführt – danach wird abgebrochen.
✅ Vermeidet unbeabsichtigtes Überschreiben.
✅ Spiegelt die reale Logik: „Wenn nicht A, dann prüfe B…“

Möglicher Prompt:

Schreibe eine Notenbewertung mit if...else if...else für die Notenstufen.
Verwende >= statt >, damit 90 "Sehr gut" ergibt.
Stelle sicher, dass nur eine Bewertung gesetzt wird – kein Überschreiben durch mehrere if.
