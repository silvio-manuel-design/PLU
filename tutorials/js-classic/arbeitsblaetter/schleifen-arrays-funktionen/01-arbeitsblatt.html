Aufgabe 5 (7 Punkte)

Gegeben ist folgende Funktion:

function summeBerechnen(arr) {
  let sum = 0;
  let i = 0;
  while (i < arr.length) {
    sum += arr[i];
    i++;
  }
  return sum;
}

a) Warum ist hier eine while-Schleife akzeptabel, obwohl die Anzahl der Durchläufe bekannt ist? (2 P)
b) Wie könnte man die gleiche Logik mit einer for-Schleife kompakter schreiben? (2 P)
c) Warum ist es besser, das Ergebnis mit return zurückzugeben – statt direkt auszugeben? (3 P)

Aufgabe 1 (2 P)

Weil sich die Länge eines Arrays zur Laufzeit ändern kann. Eine feste Zahl führt zu Fehlern, wenn das Array später mehr oder weniger Elemente hat. array.length passt sich automatisch an.

Aufgabe 2 (2 P)

Die Funktion wird universell einsetzbar: Sie kann mit jedem Array aufgerufen werden. Globale Variablen erzeugen Abhängigkeiten und erschweren Tests.

Aufgabe 3 (2 P)

Weil Computer bei 0 beginnen zu zählen („Offset“-Konvention). Wer bei 1 beginnt, greift entweder auf undefined zu oder überschreitet den gültigen Indexbereich → „Off-by-one“-Fehler.

Aufgabe 4 (7 P)

a) • i beginnt bei 1 → erstes Element (index 0) wird übersprungen.
• i <= zahlen.length → beim letzten Durchlauf: zahlen[zahlen.length] = undefined. (2 P)
b) Die Funktion ist starr: Sie kann nur in die Konsole ausgeben. Für Webseiten (z.B. innerHTML) oder Tests ist sie nutzlos. (2 P)
c) 

function getGerade(zahlen) {
  let ergebnis = [];
  for (let i = 0; i < zahlen.length; i++) {
    if (zahlen[i] % 2 === 0) {
      ergebnis.push(zahlen[i]);
    }
  }
  return ergebnis;
}
(3 P)
