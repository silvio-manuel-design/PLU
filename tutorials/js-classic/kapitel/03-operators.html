Operators

Calculate, compare, combine: the tools that turn values into decisions.

FIRST, LET'S UNDERSTAND

In maths you know signs: plus, minus, times, divided by. They connect two things. 7 + 3 makes 10.

In JavaScript you find the same signs — and a few more. A sign that connects two values is an operator.

The big surprise: comparisons are operators too. “Is 7 greater than 3?” gives true or false. With that, a program can decide.

Calculating with numbers: + − * / % **

Operators are the verbs of JavaScript. Everything that happens to values happens through them.

You know the basic arithmetic — plus Modulo (the remainder of a division) and power (**). Increment (round++) is the short form of „increase by 1".

Typical mistakes

„7 / 2 is 3"

In JavaScript 7 / 2 is exactly 3.5 — there's no integer division like in some other languages. Decimals are normal.

„% means percent"

No — % is modulo, the remainder of a division. 7 % 2 is 1, not 0.07. For percentages, multiply by 0.07.

Ignoring a++ vs ++a

a++ returns the old value, ++a the new one — as a standalone line it hardly matters, in nested expressions it's a trap. Increment first, use it on its own line.

Decimal rounding errors

0.1 + 0.2 gives 0.30000000000000004. It's the binary system — for money, calculate in cents and round deliberately.

Pro tip

Modulo is the secret weapon: x % 2 === 0 checks even numbers, x % 10 grabs the last digit — you'll use modulo in every game.

Comparisons: === !== > < >= <=

Programs decide. Comparisons return true or false — the fuel of every condition (chapter 04).

=== is the strict equality comparison: type AND value must match. !== is its opposite. The result is always a boolean.

The == trap: == converts types before comparing ("" == 0 is true!). That produces unpredictable results — so from today on: only === and !==.

Typical mistakes

= instead of ===

if (points = 90) assigns 90 and is ALWAYS true — the most classic bug of all. Mnemonic: „comparison = three strokes, assignment = one."

Using ==

„Loose equality" delivers surprises: "" == 0 is true, "0" == false too. Nobody wants that. === always.

Comparing strings lexicographically

"10" < "9" is true — strings are compared character by character („1" < „9"). Always compare numbers as numbers.

NaN === NaN

Is false — the only value not equal to itself. Check with isNaN(x) or Number.isNaN(x).

Pro tip

ESLint automatically bans ==. From today: only === and !== — no exceptions, no discussion.

TEACHING BREAK

Fun fact: && and || don't return pure booleans in JavaScript — they return one of the operands. 'Ada' || 'Guest' gives you ‚Ada'. Logic as a value — weird, but useful.

Logic: && || !

Single comparisons are rarely enough. ‚Over 16 AND under 65' — for that you need logical operators.

&& (AND) is only true if both sides are true. || (OR) is true if at least one side is true. ! (NOT) flips the result. JavaScript evaluates left to right and stops as soon as the result is decided (short-circuit).

Typical mistakes

Confusing &&/|| with words

In code they are symbols, not words: JavaScript has no and or or — it has && and ||.

Forgetting parts of the condition

age >= 16 && < 65 is an error — the second half has no variable. Full version: age >= 16 && age < 65.

!!x without understanding

A double ! turns a value into a real boolean (!!"Ada" → true). Handy, but only useful once you understand the type conversion.

Surprising short-circuit

false && … stops early, true || … too — the right side then never runs. With function calls on the right, side effects can be swallowed.

Pro tip

|| is also the standard fallback: const name = input || 'Guest'; — when input is empty, the fallback kicks in.

Assignment operators: += -= *= /=

points = points + 10 is never written in real code. The short forms are the standard in every code you'll ever read.

+= -= *= /= %= calculate on the right and assign the result directly to the variable on the left. Also works for strings: += appends text.

Typical mistakes

Reversing the direction

10 += points is a syntax error — the variable goes on the left, the value on the right: points += 10.

Calculating without assigning

points + 10; computes 10 more but discards the result instantly. Without points += 10 nothing changes.

+= on a const

const x = 0; x += 1; throws an error — const cannot be reassigned, not even via the short form. It has to be let then.

Mixing numbers and strings

log += 5 appends „5" as text when log is a string. Keep types in mind — see chapter 02.

Pro tip

Game counters: hits += 1 or hits++ — with these you build the highscore system for the final project.
