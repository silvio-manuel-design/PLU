FIRST, LET'S UNDERSTAND

Picture an ID card. Name: Ada. Age: 16. Class: 2a. Everything on one card. Every field has a label.

You don't need five notes for one person. One card is enough. And you find everything instantly: “the age field.”

An object is exactly that for your program: a collection of labelled values. One thing — with everything belonging to it, in one place.

WORDS YOU'RE LEARNING NOW

Object / Objekt

Labelled values about ONE thing, in curly braces.

Everyday: like an ID card.

const student = { name: "Ada" };

Property / Eigenschaft

One labelled field of the object.

Everyday: one field on the ID card.

age: 16

Key / Schlüssel

The label of the field.

Everyday: the caption „age" on the form.

name

Method / Methode

A function living INSIDE an object.

Everyday: a skill of the person — „Ada can calculate."

greet() { … }

Creating objects and reading properties

So far: variables for single values, arrays for lists. But the world consists of things, not lists. Objects describe things.

An object collects labelled values in { key: value, … }. You read with a dot (.name) or brackets (["name"]). And objects can live inside objects.

Typical mistakes

Space in the key

fach note: "MT" without quotes is a syntax error. Keys with spaces need quotes — better: underscores.

Dot vs. brackets mixed up

If the key sits in a variable, only brackets work: obj[key]. The dot demands a fixed name.

Comma panic

A comma after the last entry is allowed (trailing comma) — no error. But between entries it's mandatory.

Reading dot chains blindly

course.teacher.name reads from the outside in: course → teacher → name. Every dot opens the next thing.

Pro tip

Bracket notation for dynamic keys: obj[key] — when the key sits in a variable, only the bracket works.

Changing objects: set, delete, add

ID cards change: someone moves, gets older, picks a new subject. Objects are alive.

You overwrite values with =, create new properties by simply setting them — and delete removes a field.

Typical mistakes

„const forbids changes"

With objects, const only locks the REFERENCE — the contents stay freely changeable. This confuses everyone at first.

Overusing delete

Constantly deleting and re-adding fields loses the shape. Adjust the structure instead of clearing fields away.

Space field with a dot

obj.fach note breaks instantly — fields with spaces only via brackets: obj["fach note"].

Reassigning a const object

student = { … } on a const variable is an error — the reference is fixed. Changing contents works, resetting doesn't.

Pro tip

const with objects means: THIS object stays — not: its contents freeze. That confuses everyone at first.

TEACHING BREAK

Objects are all around you: your phone has properties (colour, storage) and methods (call, take photos). Your bike, your pen, your bag. Programming with objects means describing the world the way it really is.

Methods: functions inside objects

A thing without abilities is just a data store. Methods make objects come alive: they can DO things.

A method is a function as a property — called with obj.method(). this appears here as a preview only: inside a method it points at its own object.

Typical mistakes

Calling a method without ()

greeter.greet is the function itself, not a result — the parentheses execute it.

Forcing this too early

Understand the object pattern first, then this. Juggling with this too early means fighting windmills.

Calling a method outside the object

greet("Ada") alone doesn't exist — the method lives IN the object and needs its owner in front.

Arrow function + this

Writing methods as arrow functions breaks this — just remember: normal function syntax in objects.

Pro tip

this is for later — just remember: inside a method, this points at the object it lives in. You don't need more right now.

Arrays of objects: the real data

A class is a list of students. Every student is an object. Arrays of objects are THE data format of real life.

Array + object + for...of: you walk the list with the loop from chapter 06, each element is an ID card from this chapter.

Typical mistakes

Does [1] return the name?

schoolClass[1] is a whole object — only .name fetches the name from it. Brackets first, then the dot.

JSON syntax with =

In objects it's name: "Ada" — a colon, not an equals sign. The = comes from JSON templates.

Mixing up brackets

Array = square [ ], object = curly { }. In alternation: [{ … }, { … }].

„All objects need identical fields"

JavaScript allows different fields — clean code keeps them uniform anyway. Uniformity wins.

Pro tip

Arrays of objects + for...of — with this one pattern you can solve almost any real data task. It's the linchpin of the course.

Summary

  • Object = labelled values in {} — like an ID card.
  • Dot for fixed keys, brackets for dynamic ones.
  • const locks the reference, not the contents.
  • Methods = the object's abilities, called with ().
  • Array of objects + for...of = the standard pattern of real data.
