Kapitel 07

Funktionen: Wiederverwendbarer Code

Einmal schreiben, überall einsetzen: Code in Bausteinen denken.

Einstieg 1 Aufrufen 2 Parameter 3 return 4 Zusammensetzen ✓ Checkliste Quiz

ERST MAL VERSTEHEN

Du kochst Nudeln. Du weißt, wie es geht: Wasser aufsetzen, Salz, Nudeln, abgießen. Du musst nicht jedes Mal neu nachdenken. Du kannst es — du kannst es sogar einem Freund erklären.

Eine Funktion ist so ein Wissensspeicher für dein Programm: Einmal geschrieben, so oft du willst benutzt. Du gibst ihr etwas (die Packung Nudeln), sie gibt dir etwas zurück (den Teller Nudeln).

WÖRTER, DIE DU JETZT LERNST

Funktion / function

Ein benannter Baustein mit Code, den du wiederverwenden kannst.

Alltag: wie das Rezept für Nudeln.

function gruss() { … }

Parameter / parameter

Der Wert, den die Funktion entgegennimmt.

Alltag: die Packung Nudeln, die du der Maschine gibst.

function gruss(name) { … }

Rückgabe (return) / return

Das Ergebnis, das die Funktion liefert.

Alltag: der fertige Teller.

return "Hallo!";

Aufruf / call

Das tatsächliche Benutzen der Funktion.

Alltag: „Jetzt koche ich die Nudeln."

gruss("Ada");

Funktion deklarieren und aufrufen

Bisher lief dein Code einmal durch, Zeile für Zeile. Funktionen ändern das: Code wartet auf seinen Einsatz, statt sofort zu laufen.

Deklariert wird mit function name() { … }, aufgerufen mit name(). Der Code im Körper läuft NUR beim Aufruf — die Deklaration legt ihn nur bereit.

Typische Fehler

Deklariert, nie aufgerufen

Die häufigste Anfängerfrage: „Warum passiert nichts?" — Weil gruss() nirgends steht. Erst der Aufruf startet den Code.

Klammern beim Aufruf vergessen

gruss ohne () ist die Funktion SELBST (als Wert), kein Aufruf. Die Klammern sind der Startknopf.

Namen doppelt vergeben

Zwei Funktionen mit demselben Namen: die zweite überschreibt die erste. Namen sollen einzigartig und sprechend sein.

„Funktionen müssen etwas zurückgeben"

Nicht nötig. Funktionen dürfen auch nur etwas TUN (anzeigen, ändern) — return ist eine Option, keine Pflicht.

Profi-Tipp

Funktionsnamen sind Verben: gruss, berechne, zeige. Wer ein Verb liest, weiß sofort, was passiert.

Parameter: Eingaben machen Funktionen flexibel

Eine Funktion ohne Parameter ist ein Rezept für genau ein Gericht. Mit Parametern wird sie zur Küchenmaschine: Rein damit, was du hast.

Parameter sind Platzhalter in den Klammern der Deklaration. Beim Aufruf werden sie mit echten Werten gefüllt — mehrere durch Komma getrennt.

Typische Fehler

Reihenfolge vertauscht

function teile(a, b) mit teile(2, 10) teilt 2 durch 10 — die Reihenfolge der Argumente zählt.

Zu wenige Argumente

summe(3) ergibt NaN — fehlende Parameter sind undefined. Anzahl muss passen.

Shadowing-Verwirrung

Parameter heißt wie eine Variable außerhalb? Innerhalb der Funktion zählt nur der Parameter — das verwirrt beim Lesen. Namen eindeutig halten.

„Parameter sind wichtigere Variablen"

Nein — sie sind nur Platzhalter für den Aufruf. Nach außen existieren sie nicht.

Profi-Tipp

Parameter sind wie die Felder eines Formulars: Die Funktion definiert, WAS sie braucht — der Aufrufer füllt sie aus.

DIDAKTISCHE PAUSE

Funktionen sind übrigens Teamarbeit im Kleinformat: Dein Code sagt der Funktion: „Hier, kümmere dich drum." Die Funktion antwortet: „Erledigt, hier ist das Ergebnis." Guter Code ist ein gut geführtes Gespräch.

return: Ergebnisse zurückgeben

Bisher zeigen deine Funktionen etwas an. Mächtig werden sie erst, wenn sie Ergebnisse ZURÜCKGEBEN — damit kannst du weiterrechnen.

return beendet die Funktion und liefert einen Wert an den Aufrufer. Danach kommt nichts mehr. Der Rückgabewert ist ein ganz normaler Wert: zuweisen, rechnen, ausgeben.

Typische Fehler

console.log mit return verwechselt

Anzeigen ist nicht zurückgeben. console.log zeigt dir etwas, return gibt deinem Programm etwas — zwei verschiedene Welten.

Code nach return

return beendet die Funktion SOFORT. Alles danach ist unreachable — totter Code, der nie läuft.

return vergessen

Eine Funktion ohne return gibt undefined zurück — damit lässt sich nicht weiterrechnen.

Mehrere return-Pfade übersehen

Bei if/else braucht jeder Zweig sein return — sonst geht ein Weg mit undefined zurück.

Profi-Tipp

console.log ist für Menschen, return ist für dein Programm. Profi-Regel: Erst return denken, dann anzeigen.

Kleine Funktionen zusammensetzen

Große Programme sind keine langen Funktionen. Sie sind viele kleine, klare Funktionen, die zusammenarbeiten.

Das Muster: Funktionen rufen andere Funktionen auf. Im Beispiel kombiniert zeigeNote die kleine Helferin noteAlsText. Die Arrow-Funktion siehst du hier nur zum Lesen — selbst schreiben lernst du sie später.

Typische Fehler

Eine Funktion für alles

Die „mega-Funktion" mit 100 Zeilen kann niemand mehr lesen — auch du in drei Wochen nicht. Klein schneiden.

Arrow-Funktionen sofort selbst schreiben

Erst das function-Muster sicher können, dann die Kurzform. Wer mit der Kurzform anfängt, verheddert sich in Klammern.

Rückgabe als Argument nicht erkennen

zeigeNote(noteAlsText(2)): innen wird zuerst gerechnet, dann übergeben. Von innen nach außen lesen.

Zu viele Stufen auf einmal

Vier Ebenen verschachtelte Aufrufe überfordern am Anfang — baue Schicht für Schicht und teste jede einzeln.

Profi-Tipp

Eine Funktion = eine Aufgabe. Wer zwei Aufgaben sieht, baut zwei Funktionen. Das ist kein Mehraufwand — es ist die Entlastung.

Check: Kannst du das schon?

Jede Funktion eine Aufgabe, das Ergebnis wandert per return weiter.

Zusammenfassung

  • Funktion = benannter, wiederverwendbarer Baustein; Körper läuft nur beim Aufruf.
  • Parameter = Eingänge, return = Ausgang.
  • console.log zeigt, return liefert.
  • Kleine Funktionen rufen einander — so entstehen Programme.
  • Eine Funktion, eine Aufgabe.
