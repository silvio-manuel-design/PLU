FIRST, LET'S UNDERSTAND

You make decisions all day. If it rains, you take an umbrella. If not, you leave it at home. You check the world. Then you act.

A program can do the same. It checks a condition. Then it runs one path or the other.

Most important: the program reads your condition. It never decides on its own. You give it the rules.

WORDS YOU'RE LEARNING NOW

Condition / Bedingung

A check that returns true or false.

Everyday: like „is it raining right now?“

if (age >= 16)

Branch / Verzweigung

The point where the program chooses the path.

Everyday: like a fork in the road.

if … else …

Code block / Code-Block

Several lines that belong together. Stands in curly braces.

Everyday: like a work step with several parts.

{ … }

Decision / Entscheidung

The result of the check: this path or that one.

Everyday: like your umbrella decision in the morning.

age >= 16 ? "yes" : "no"

if/else — the basic decision

Conditions are the moment a script comes alive off the paper: it reacts differently to different inputs.

if checks a boolean expression in parentheses. If it's true, the block in {} runs, otherwise the else branch. With else if you chain as many cases as you like — the first match wins.

Exactly the else-if chain from the example — as a demo to trace along.

Typical mistakes

Forgetting parentheses after if

if points >= 50 without parentheses is a syntax error. The condition ALWAYS goes in ( ).

No {} for one-liners

Without braces only the first line belongs to the condition. Later additions then ALWAYS run — always set {}.

= instead of ===

if (points = 90) assigns 90 and is always true — the costliest mistake. Compare with ===.

Wrong chain order

With >= chains the largest value must come first, or an early branch swallows the later ones. Build descending!

Pro tip

Read else-if chains top to bottom like a menu: the first match wins, the rest is skipped.

Combining comparisons & logic

Real conditions are rarely simple: ‚adult AND member' or ‚weekend OR holiday'. Chapter 03 delivered the building blocks — here you assemble them.

Combine comparisons with && and ||. With mixed conditions, add parentheses — that keeps precedence clear and readable.

Typical mistakes

Forgetting parentheses in mixed conditions

a && b || c is ambiguous without parentheses — which first? Write (a && b) || c and mean what you write.

Mixing && and || unparenthesized

JavaScript evaluates && before || — without parentheses you get logic you didn't intend. Parentheses are free, use them.

Double-checking boolean variables

if (loggedIn === true) is redundant — loggedIn already IS the value if needs: if (loggedIn).

Awkward negation instead of else

if (!loggedIn) { … } PLUS if (loggedIn) { … } is doubled. One side is enough — the other belongs in else.

Pro tip

A variable that already is true/false needs no comparison: if (loggedIn) instead of if (loggedIn === true).

TEACHING BREAK

Your day is full of conditions: when the alarm rings you get up — otherwise you turn around. if/else learned from you, not the other way around.

switch for many cases

Long else-if chains over the same value become unreadable. switch is the tidy alternative for 3+ cases.

switch compares one value against many cases. break ends a case — without break all following cases run through („fall-through"). default catches everything else.

Typical mistakes

Forgetting break

Without break all cases FROM THE MATCH onward run — with school grades you get „Very good Good Satisfactory" at once.

case with conditions

case points >= 50: doesn't work — switch compares values with ===, no ranges. For ranges: if/else.

Forgetting default

What happens for value 6? Without default: nothing — silently. The rest case should always be covered.

switch for boolean conditions

switch (true) tricks exist — but boolean logic belongs in if/else. switch is for fixed values: weekdays, grades, menus.

Pro tip

Forgetting break in a switch is JavaScript trap #1 in report-card programs — always read your code aloud at the fall-through case.

The ternary operator (short decisions)

Sometimes a decision is only worth one line: one value or the other. The ternary operator ? : is the short form.

condition ? valueIfTrue : valueIfFalse — ideal for assignments and template literals where an if/else would be clunky.

Typical mistakes

Nesting multiple ternaries

a ? b : c ? d : e becomes unreadable. One decision = one ternary; anything complex belongs in if/else.

Abusing it for side effects

condition ? console.log(a) : console.log(b) is possible but ugly — ternary delivers VALUES, if/else does ACTIONS.

Forgetting the colon

age >= 16 ? "Adult" without : … is a syntax error — both branches belong to the decision.

Complex conditions without parentheses

a && b ? x : y makes the reader guess — parentheses make it unambiguous: (a && b) ? x : y.

Pro tip

Ternary is for ONE decision between TWO values. Anything more complex belongs in if/else — no golfing.

Summary

  • if/else = branching; build else-if chains from large to small.
  • The biggest trap: = instead of === in if.
  • Multiple conditions: set parentheses, use && and || deliberately.
  • switch = tidy for many cases of one value, don't forget break.
  • Ternary ? : for short two-value choices, otherwise if/else.
