The third pillar — and where JavaScript lives

You already know HTML and CSS — together they build websites that look polished: structure and styling in place. But they are silent. JavaScript is the third pillar of the web: HTML gives content its structure, CSS gives its appearance a shape, and JavaScript gives its behaviour a pulse. No JavaScript means no buttons that react, no forms that validate, no content that moves. Before you write the language, you need to know where it actually lives — because JavaScript never lives alone, it always moves in with HTML.

JavaScript is a client-side scripting language: your browser reads and runs the code — not a server somewhere on the web, but right on your device, every time the page loads. A scripting language needs a host: an HTML document. There are three ways to move JavaScript in — and they differ a lot in tidiness.

Everything that runs in the browser — what visitors see and touch — is called the frontend, and JavaScript is its language. Its counterpart, the backend on the server, comes next semester with Node.js and PHP.

  • 1. Inline — JavaScript directly in an HTML attribute. Fast, but messy: content and behaviour mix, and the code cannot be reused anywhere. For school: off limits.
  • 2. Internal — a <script> element inside the HTML document. Better, but larger projects get cluttered, and multiple pages cannot share the code.
  • 3. External — the code lives in its own file (e.g. main.js) and is linked in. This is the standard you always follow: structure (HTML), style (CSS) and behaviour (JS) live in three separate files. Everything stays maintainable, the browser can cache the file — and your code works on every page.

Where does the link go? In the past, <script> sat at the end of the <body>, so the HTML already existed before the script ran. Today the cleanest spot is the <head> — with the defer attribute: the browser loads main.js in parallel with the HTML but only executes it after the page is fully built. You get both: full loading speed and the certainty that every element exists.

  1. Create a folder my-first-site with two files: index.html and main.js.
  2. Write the basic scaffold into index.html (with <!DOCTYPE html>, head and body).
  3. Add inside <head>: <script src="main.js" defer></script>.
  4. Write into main.js: console.log("JavaScript has moved in!");
  5. Open the page in your browser and check the console (F12) — your text is there.

Common mistakes

Path without the dot

src="/main.js" looks at the server root, src="main.js" looks next to the HTML file. For local projects: almost never use a leading slash.

Script before the element

Without defer (or if the script sits in the <head> without it), the code runs before the HTML exists — document.getElementById() finds nothing.

Inline "just for a moment"

The one quick onclick almost never stays single. Start with the external file from day one.

Two scripts blocking each other

Plain <script> elements stop the page from loading. With defer everything stays smooth.

Pro tip

Remember the rule of thumb "external + defer" — it carries you through the whole school year. The only exception: tiny demos in a single document, as in some exercises here. And: the filename main.js is convention, not law — but conventions read better later.

Your first output: console.log()

Imagine writing your first program — and… nothing visible happens. That's exactly where JavaScript starts: it has to tell you what it's doing. The console is your program's notebook: everything you want to think about lands there.

console.log() prints text or values to the console. Open it in your browser with F12 (tab "Console"). It is the most important debugging tool — and it never interrupts your program.

Try the console

  1. Open VS Code and create a file hello.js.
  2. Write into it: console.log("Hello, world!");
  3. Open your browser's developer console (F12 → Console).
  4. Run the file from an HTML document via <script src="hello.js"></script>.
  5. Find your output in the console. Congratulations — that was your first program!

Common mistakes

Missing quotes

console.log(Hello) throws an error because JavaScript looks for a variable named Hello. Text always goes in quotes: console.log("Hello").

Forgotten parentheses

console.log "Hello" does not work — a call always needs ().

Searching the page instead of the console

console.log never writes to the web page. Nothing found? The output lives in the console, not the browser window.

Semicolon panic

A missing ; is usually not an error in JavaScript. Still always add it — it makes the end of the statement visible.

Pro tip

Multiple values at once: console.log("Name:", name, "Age:", age) — separate with commas instead of stitching text together. More readable, fewer error sources.

TEACHING BREAK

A little time travel: JavaScript was written in 1995 — almost on the side — in about ten days. Brendan Eich was originally asked to build a small scripting language for the browser, and from those ten days came the most widely used programming language in the world. By the way, it was not always called JavaScript — briefly "LiveScript", even shorter "Mocha". What remains: the language you are learning carries 30 years of history. No pressure. 😉

Output for visitors: innerHTML

Only you can see the console. A real website has to show visitors something — a welcome message, a result, a list. innerHTML lets JavaScript write directly into the page: this is the moment your page comes alive.

Every HTML element can be reached via document.getElementById(). With innerHTML you replace its content. The element needs an id.

What is the DOM? When the browser loads your HTML, it turns it into a living tree of objects — the Document Object Model (DOM). Every element (<p>, <h1>, <button>) becomes a node that JavaScript can reach and change. document.getElementById("greeting") fetches exactly such a node — and innerHTML changes it. You just used the DOM without knowing its name. Now you do — in chapter 09 you will get to know it properly.

Bring the page to life

  1. Create a file index.html with a paragraph: <p id="greeting"></p>
  2. Add a <script> element below it.
  3. Write into the script: document.getElementById("greeting").innerHTML = "Welcome!"
  4. Open the page in your browser — your text appears.

Common mistakes

Typo in the ID

getElementById("Greeting") finds nothing if the ID is greeting. Case matters — type it exactly.

Element without an id

Without an id, JavaScript cannot address the element. Always assign one before using it in the script.

Script before the element

If the <script> sits before the element in the HTML, the element does not exist yet. Put the script at the end of the body.

Quotes inside the string

innerHTML = "She said "hello"" breaks. Set inner quotes differently: "She said 'hello'".

Pro tip

First const element = document.getElementById("greeting"), then element.innerHTML = … — fetch once, use many times. Saves typos.

Popups & input: alert() and prompt()

You will often see alert() and prompt() in old tutorials. You should know what they do — and why professionals rarely use them: both block the page until someone clicks.

alert("text") shows a message with an OK button. prompt("question") asks for input and returns it as text. Both stop your program and get annoying with frequent use — for real input you use form fields (coming later in the course).

Feel the blockers

Notice how the page behind the popup freezes.

  1. Write alert("Hi!") into a script and load the page.
  2. Replace it with const name = prompt("What's your name?").
  3. Print the name to the console: console.log(name).
  4. Compare: why is a form field the better solution? Write an answer in your own words (3 sentences).

Common mistakes

Not saving the prompt() result

prompt("What's your name?") alone vanishes immediately. Catch the result in a variable: const name = prompt(…).

Several popups in a row

Every alert() stops everything. Four popups in a row = four forced clicks. Use the console for intermediate values.

Expecting a number from prompt()

prompt() always returns text. "5" + "3" gives "53". Convert numbers first (coming in chapter 03).

document.write() from old tutorials

⚠️ Legacy: document.write() only works while the page loads and wipes the whole page afterwards. Never use it — innerHTML is the modern replacement.

Pro tip

Popups have one legitimate place: small debug messages in your own development workflow. But anything users should see belongs in the page (innerHTML) — not in a window in front of it.

Summary

  • Including JavaScript means: external file, in the <head>, with defer.
  • The console (console.log) is your tool for understanding — visitors never see it.
  • innerHTML writes visibly into the page — the element needs an id.
  • The browser turns HTML into the DOM's tree of objects — getElementById fetches one node.
  • alert() and prompt() block the page; document.write() is no longer used.
