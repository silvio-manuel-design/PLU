Die dritte Säule — und wo JavaScript wohnt

Du kannst Webseiten mit HTML und CSS bauen, die aussehen wie aus einem Guss: Struktur und Gestaltung sitzen. Aber sie sind still. JavaScript ist die dritte Säule des Webs: HTML gibt dem Inhalt seine Struktur, CSS seinem Aussehen seine Gestalt, und JavaScript seinem Verhalten seinen Puls. Ohne JavaScript keine Buttons, die reagieren, keine Formulare, die prüfen, keine Inhalte, die sich bewegen. Bevor du die Sprache schreibst, musst du wissen, wo sie überhaupt wohnt — denn JavaScript lebt nie allein, es zieht immer bei HTML ein.

JavaScript ist eine clientseitige Skriptsprache: Der Code wird von deinem Browser gelesen und ausgeführt — nicht von einem Server irgendwo im Netz, sondern direkt auf deinem Gerät, jedes Mal, wenn die Seite lädt. Eine Skriptsprache braucht einen Wirt: ein HTML-Dokument. Es gibt drei Arten, JavaScript einzuziehen — und sie unterscheiden sich stark in Ordnung und Unordnung.

Alles, was im Browser läuft und die Besucher sehen und anfassen, nennt man Frontend — JavaScript ist die Sprache des Frontends. Das Gegenstück, das Backend auf dem Server, kommt im Sommersemester dazu — mit Node.js und PHP.

Die drei Arten — im Vergleich

  • 1. Inline — JavaScript direkt in einem HTML-Attribut. Schnell, aber unordentlich: Inhalt und Verhalten vermischen sich, und der Code ist nirgends wieder verwendbar. Für den Schulalltag: tabu.
  • 2. Intern — ein <script>-Element direkt im HTML-Dokument. Besser, aber bei größeren Projekten wird die Datei unübersichtlich, und mehrere Seiten können den Code nicht teilen.
  • 3. Extern — der Code liegt in einer eigenen Datei (z. B. main.js) und wird verlinkt. Das ist der Standard, an dem du dich immer orientierst: Struktur (HTML), Gestalt (CSS) und Verhalten (JS) liegen in drei getrennten Dateien. So bleibt alles wartbar, der Browser kann die Datei cachen — und dein Code ist auf jeder Seite nutzbar.

Wo der Link hingehört

Wo gehört der Link hin? Früher stand das <script> am Ende des <body>, damit das HTML schon existiert, bevor das Script läuft. Heute ist der sauberste Platz der <head> — mit dem Attribut defer: Der Browser lädt main.js parallel zum HTML, führt es aber erst aus, nachdem die Seite komplett aufgebaut ist. Du bekommst beides: volle Ladegeschwindigkeit und die Sicherheit, dass alle Elemente bereits existieren.

  1. Erstelle einen Ordner meine-erste-seite mit zwei Dateien: index.html und main.js.
  2. Schreibe in index.html das Grundgerüst (mit <!DOCTYPE html>, head und body).
  3. Setze im <head>: <script src="main.js" defer></script>.
  4. Schreibe in main.js: console.log("JavaScript ist eingezogen!");
  5. Öffne die Seite im Browser und prüfe die Konsole (F12) — dein Text steht dort.

Typische Fehler

Pfad ohne Punkt

src="/main.js" sucht am Server-Stamm, src="main.js" sucht neben der HTML-Datei. Für lokale Projekte: fast immer ohne führenden Slash.

Script vor dem Element

Ohne defer (oder wenn das Script im <head> ohne defer steht) läuft der Code, bevor das HTML existiert — document.getElementById() findet dann nichts.

Inline „nur für einen Moment"

Der eine schnelle onclick bleibt fast nie bei einem. Fange vom ersten Tag an mit der externen Datei an.

Zwei Scripts, die sich blockieren

Normale <script>-Elemente stoppen das Laden der Seite. Mit defer bleibt alles flüssig.

Profi-Tipp

Merk dir die Faustregel „extern + defer" — sie trägt dich durch das ganze Schuljahr. Einzige Ausnahme: winzige Demos in einem einzigen Dokument, wie in manchen Übungen hier. Und: Der Dateiname main.js ist Konvention, kein Gesetz — aber Konventionen lesen sich später leichter.

  • Ich kann erklären, was HTML, CSS und JavaScript jeweils für eine Säule des Webs sind.
  • Ich kann die drei Einbindungsarten (inline, intern, extern) unterscheiden und zeigen.
  • Ich kann begründen, warum externe Dateien bevorzugt werden.
  • Ich kann ein externes Script im <head> mit defer einbinden und den Unterschied zum Ende des body erklären.

Deine erste Ausgabe: console.log()

Stell dir vor, du schreibst dein erstes Programm — und es passiert… nichts Sichtbares. Genau hier setzt JavaScript an: Es muss dir sagen, was es tut. Die Konsole ist das Notizbuch deines Programms: alles, was du dir zum Nachdenken notieren willst, landet dort.

console.log() gibt Text oder Werte in der Konsole aus. Die Konsole öffnest du in deinem Browser mit F12 (Reiter „Konsole"). Sie ist das wichtigste Werkzeug zum Debuggen — und sie unterbricht dein Programm nie.

Konsole ausprobieren

  1. Öffne VS Code und erstelle eine Datei hallo.js.
  2. Schreibe hinein: console.log("Hallo, Welt!");
  3. Öffne die Entwicklerkonsole deines Browsers (F12 → Konsole).
  4. Führe die Datei in einem HTML-Dokument per <script src="hallo.js"></script> aus.
  5. Finde deine Ausgabe in der Konsole. Gratuliere — das war dein erstes Programm!

Typische Fehler

Vergessene Anführungszeichen

console.log(Hallo) erzeugt einen Fehler, weil JavaScript Hallo als Variable sucht. Text gehört immer in Anführungszeichen: console.log("Hallo").

Runde Klammern vergessen

console.log "Hallo" funktioniert nicht — der Aufruf braucht immer ().

Suchen auf der Seite statt in der Konsole

console.log schreibt nie auf die Webseite. Nichts gefunden? Dann liegt die Ausgabe in der Konsole, nicht im Browserfenster.

Semikolon-Panik

Fehlendes ; ist in JavaScript meist kein Fehler. Trotzdem immer setzen — es macht das Ende der Anweisung sichtbar.

Profi-Tipp

Mehrere Werte auf einmal: console.log("Name:", name, "Alter:", alter) — mit Kommas trennen statt Text zusammenzubasteln. Lesbarer, weniger Fehlerquellen.

  • Ich kann erklären, wozu die Konsole dient und wie man sie öffnet.
  • Ich kann zeigen, wie console.log("Text") geschrieben wird — inklusive Anführungszeichen und Klammern.
  • Ich kann den Unterschied zwischen Ausgabe in der Konsole und Ausgabe auf der Seite erklären.

DIDAKTISCHE PAUSE

Kleine Zeitreise: JavaScript wurde 1995 — fast nebenbei — in etwa zehn Tagen geschrieben. Brendan Eich sollte ursprünglich eine kleine Skriptsprache für den Browser bauen, und aus diesen zehn Tagen wurde die am weitesten verbreitete Programmiersprache der Welt. Sie hieß übrigens nicht immer JavaScript — kurz „LiveScript", noch kürzer „Mocha". Was bleibt: Die Sprache, die du gerade lernst, trägt 30 Jahre Geschichte in sich. Kein Druck. 😉

Ausgabe für Besucher: innerHTML

Die Konsole sieht nur du. Eine echte Webseite muss Besucher etwas zeigen — einen Willkommensgruß, ein Ergebnis, eine Liste. innerHTML lässt JavaScript direkt in die Seite schreiben: das ist der Moment, in dem deine Seite lebendig wird.

Jedes HTML-Element ist über document.getElementById() erreichbar. Mit innerHTML ersetzt du seinen Inhalt. Das Element braucht eine id.

Was ist das DOM? Der Browser verwandelt dein HTML beim Laden in einen lebendigen Objektbaum — das Document Object Model (DOM). Jedes Element (<p>, <h1>, <button>) wird zu einem Knoten, den JavaScript erreichen und verändern kann. document.getElementById("gruss") holt genau einen solchen Knoten — und innerHTML verändert ihn. Du hast das DOM gerade benutzt, ohne es zu wissen. Ab jetzt kennst du seinen Namen — in Kapitel 09 lernst du es richtig gut.

Seite zum Leben erwecken

  1. Erstelle eine Datei index.html mit einem Absatz: <p id="gruss"></p>
  2. Füge darunter ein <script>-Element hinzu.
  3. Schreibe in das Script: document.getElementById("gruss").innerHTML = "Willkommen!"
  4. Öffne die Seite im Browser — dein Text erscheint.

Typische Fehler

ID-Schreibfehler

getElementById("Gruss") findet nichts, wenn die ID gruss heißt. Groß-/Kleinschreibung zählt — exakt abtippen.

Element ohne id

Ohne id kann JavaScript das Element nicht ansprechen. Immer eine vergeben, bevor du sie im Script verwendest.

Script vor dem Element

Steht das <script> im HTML vor dem Element, existiert das Element noch nicht. Script ans Ende des body setzen.

Anführungszeichen im String

innerHTML = "Sie sagte "Hallo"" bricht. Innere Anführungszeichen anders setzen: "Sie sagte 'Hallo'".

Profi-Tipp

Erst const element = document.getElementById("gruss"), dann element.innerHTML = … — einmal holen, mehrfach nutzen. Spart Tippfehler.

  • Ich kann erklären, warum ein Element eine id braucht, um es mit JavaScript anzusprechen.
  • Ich kann zeigen, wie innerHTML den Inhalt eines Elements ersetzt.
  • Ich kann erklären, warum das Script ans Ende des body gehört.

Popups & Eingaben: alert() und prompt()

Du wirst in alten Tutorials oft alert() und prompt() sehen. Du solltest wissen, was sie tun — und warum Profis sie nur selten einsetzen: Beide blockieren die Seite, bis jemand klickt.

alert("Text") zeigt eine Meldung mit OK-Button. prompt("Frage") fragt nach einer Eingabe und liefert sie als Text zurück. Beides stoppt dein Programm und nervt bei häufiger Nutzung — für echte Eingaben verwendet man Formularfelder (kommt später im Kurs).

Blocker spüren

Merke, wie die Seite hinter dem Popup eingefroren ist.

  1. Schreibe alert("Hallo!") in ein Script und lade die Seite.
  2. Ersetze es durch const name = prompt("Wie heißt du?").
  3. Gib den Namen in der Konsole aus: console.log(name).
  4. Vergleiche: Warum ist ein Formularfeld die bessere Lösung? Notiere eine Antwort in deinen eigenen Worten (3 Sätze).

Typische Fehler

prompt()-Rückgabe nicht speichern

prompt("Wie heißt du?") allein verschwindet sofort. Ergebnis in einer Variable auffangen: const name = prompt(…).

Mehrere Popups hintereinander

Jedes alert() stoppt alles. Vier Popups in Folge = vier Klicks Zwang. Nutze die Konsole für Zwischenwerte.

prompt()-Eingabe als Zahl erwarten

prompt() liefert immer Text. "5" + "3" ergibt "53". Zahlen erst umwandeln (kommt in Kapitel 03).

document.write() aus alten Tutorials

⚠️ Historisch: document.write() funktioniert nur während des Seitenladens und löscht danach die ganze Seite. Nie verwenden — innerHTML ist der moderne Ersatz.

Profi-Tipp

Popups haben einen legitimen Platz: kleine Debug-Meldungen im eigenen Entwicklungsalltag. Aber alles, was User sehen sollen, gehört in die Seite (innerHTML) — nicht in ein Fenster davor.

  • Ich kann erklären, warum alert() und prompt() die Seite blockieren.
  • Ich kann erklären, warum document.write() nicht mehr verwendet wird.

Check: Kannst du das schon?

Extern mit defer, weil der Browser die Datei parallel zum HTML lädt und das Script erst nach dem Aufbau der Seite ausführt — so existieren alle Elemente, bevor das Script sie anfasst.

Zusammenfassung

  • JavaScript einbinden heißt: externe Datei, im <head>, mit defer.
  • Die Konsole (console.log) ist dein Werkzeug zum Verstehen — Besucher sehen sie nie.
  • innerHTML schreibt sichtbar in die Seite — dafür braucht das Element eine id.
  • Der Browser verwandelt HTML in den Objektbaum des DOM — getElementById holt einen Knoten.
  • alert() und prompt() blockieren die Seite; document.write() wird nicht mehr verwendet.
