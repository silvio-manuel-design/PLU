Kapitel 01

Einführung & Ausgabe

Wo JavaScript hingehört — und wie du Inhalte sichtbar machst.

Deine erste Ausgabe: console.log()

Stell dir vor, du schreibst dein erstes Programm — und es passiert… nichts Sichtbares. Genau hier setzt JavaScript an: Es muss dir sagen, was es tut. Die Konsole ist das Notizbuch deines Programms: alles, was du dir zum Nachdenken notieren willst, landet dort.

console.log() gibt Text oder Werte in der Konsole aus. Die Konsole öffnest du in deinem Browser mit F12 (Reiter „Konsole"). Sie ist das wichtigste Werkzeug zum Debuggen — und sie unterbricht dein Programm nie.

Konsole ausprobieren

  1. Öffne VS Code und erstelle eine Datei hallo.js.
  2. Schreibe hinein: console.log("Hallo, Welt!");
  3. Öffne die Entwicklerkonsole deines Browsers (F12 → Konsole).
  4. Führe die Datei in einem HTML-Dokument per <script src="hallo.js"></script> aus.
  5. Finde deine Ausgabe in der Konsole. Gratuliere — das war dein erstes Programm!

Typische Fehler

Vergessene Anführungszeichen

console.log(Hallo) erzeugt einen Fehler, weil JavaScript Hallo als Variable sucht. Text gehört immer in Anführungszeichen: console.log("Hallo").

Runde Klammern vergessen

console.log "Hallo" funktioniert nicht — der Aufruf braucht immer ().

Suchen auf der Seite statt in der Konsole

console.log schreibt nie auf die Webseite. Nichts gefunden? Dann liegt die Ausgabe in der Konsole, nicht im Browserfenster.

Semikolon-Panik

Fehlendes ; ist in JavaScript meist kein Fehler. Trotzdem immer setzen — es macht das Ende der Anweisung sichtbar.

Profi-Tipp

Mehrere Werte auf einmal: console.log("Name:", name, "Alter:", alter) — mit Kommas trennen statt Text zusammenzubasteln. Lesbarer, weniger Fehlerquellen.

  • Ich kann erklären, wozu die Konsole dient und wie man sie öffnet.
  • Ich kann zeigen, wie console.log("Text") geschrieben wird — inklusive Anführungszeichen und Klammern.
  • Ich kann den Unterschied zwischen Ausgabe in der Konsole und Ausgabe auf der Seite erklären.

Ausgabe für Besucher:innen: innerHTML

Die Konsole sieht nur du. Eine echte Webseite muss Besucher:innen etwas zeigen — einen Willkommensgruß, ein Ergebnis, eine Liste. innerHTML lässt JavaScript direkt in die Seite schreiben: das ist der Moment, in dem deine Seite lebendig wird.

Jedes HTML-Element ist über document.getElementById() erreichbar. Mit innerHTML ersetzt du seinen Inhalt. Das Element braucht eine id.

Was ist das DOM? Der Browser verwandelt dein HTML beim Laden in einen lebendigen Objektbaum — das Document Object Model (DOM). Jedes Element (<p>, <h1>, <button>) wird zu einem Knoten, den JavaScript erreichen und verändern kann. document.getElementById("gruss") holt genau einen solchen Knoten — und innerHTML verändert ihn. Du hast das DOM gerade benutzt, ohne es zu wissen. Ab jetzt kennst du seinen Namen — in Kapitel 09 lernst du es richtig gut.

Seite zum Leben erwecken

  1. Erstelle eine Datei index.html mit einem Absatz: <p id="gruss"></p>
  2. Füge darunter ein <script>-Element hinzu.
  3. Schreibe in das Script: document.getElementById("gruss").innerHTML = "Willkommen!"
  4. Öffne die Seite im Browser — dein Text erscheint.

Typische Fehler

ID-Schreibfehler

getElementById("Gruss") findet nichts, wenn die ID gruss heißt. Groß-/Kleinschreibung zählt — exakt abtippen.

Element ohne id

Ohne id kann JavaScript das Element nicht ansprechen. Immer eine vergeben, bevor du sie im Script verwendest.

Script vor dem Element

Steht das <script> im HTML vor dem Element, existiert das Element noch nicht. Script ans Ende des body setzen.

Anführungszeichen im String

innerHTML = "Sie sagte "Hallo"" bricht. Innere Anführungszeichen anders setzen: "Sie sagte 'Hallo'".

Profi-Tipp

Erst const element = document.getElementById("gruss"), dann element.innerHTML = … — einmal holen, mehrfach nutzen. Spart Tippfehler.

  • Ich kann erklären, warum ein Element eine id braucht, um es mit JavaScript anzusprechen.
  • Ich kann zeigen, wie innerHTML den Inhalt eines Elements ersetzt.
  • Ich kann erklären, warum das Script ans Ende des body gehört.

Popups & Eingaben: alert() und prompt()

Du wirst in alten Tutorials oft alert() und prompt() sehen. Du solltest wissen, was sie tun — und warum Profis sie nur selten einsetzen: Beide blockieren die Seite, bis jemand klickt.

alert("Text") zeigt eine Meldung mit OK-Button. prompt("Frage") fragt nach einer Eingabe und liefert sie als Text zurück. Beides stoppt dein Programm und nervt bei häufiger Nutzung — für echte Eingaben verwendet man Formularfelder (kommt später im Kurs).

Blocker spüren

Merke, wie die Seite hinter dem Popup eingefroren ist.

  1. Schreibe alert("Hallo!") in ein Script und lade die Seite.
  2. Ersetze es durch const name = prompt("Wie heißt du?").
  3. Gib den Namen in der Konsole aus: console.log(name).
  4. Vergleiche: Warum ist ein Formularfeld die bessere Lösung? Notiere eine Antwort in deinen eigenen Worten (3 Sätze).

Typische Fehler

prompt()-Rückgabe nicht speichern

prompt("Wie heißt du?") allein verschwindet sofort. Ergebnis in einer Variable auffangen: const name = prompt(…).

Mehrere Popups hintereinander

Jedes alert() stoppt alles. Vier Popups in Folge = vier Klicks Zwang. Nutze die Konsole für Zwischenwerte.

prompt()-Eingabe als Zahl erwarten

prompt() liefert immer Text. "5" + "3" ergibt "53". Zahlen erst umwandeln (kommt in Kapitel 03).

document.write() aus alten Tutorials

⚠️ Historisch: document.write() funktioniert nur während des Seitenladens und löscht danach die ganze Seite. Nie verwenden — innerHTML ist der moderne Ersatz.

Profi-Tipp

Popups haben einen legitimen Platz: kleine Debug-Meldungen im eigenen Entwicklungsalltag. Aber alles, was Benutzer:innen sehen sollen, gehört in die Seite (innerHTML) — nicht in ein Fenster davor.

  • Ich kann erklären, warum alert() und prompt() die Seite blockieren.
  • Ich kann erklären, warum document.write() nicht mehr verwendet wird.

Warum schlecht?

Vage: keine Methode genannt, kein Ziel, kein Level. Die Antwort wird generisch und lang.

Guter Prompt „Du bist mein JavaScript-Tutor. Erkläre mir den Unterschied zwischen console.log() und innerHTML an einem Beispiel einer Begrüßungs-Webseite. Danach gib mir eine Mini-Aufgabe, mit der ich es selbst üben kann — und prüfe meine Lösung streng."

Warum gut?

Rolle, Gegenstand, Beispielkontext, gewünschte Übung und Feedback sind klar. Die KI liefert genau das, was du brauchst.
