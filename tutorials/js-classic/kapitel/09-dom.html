ERST MAL VERSTEHEN

Dein HTML baut ein Haus: Wände, Türen, Fenster. Bisher blieb es leer und still, sobald der Browser fertig gebaut hatte.

Das DOM ist der Bauplan dieses Hauses, den der Browser aus deinem HTML macht. Und JavaScript kann den Plan verändern, während du hineinschaust: Ein Fenster einfärben, eine Tür öffnen, ein Zimmer dazubauen.

Du hast das DOM schon in Kapitel 01 kennengelernt. Jetzt wird es dein Werkzeug.

WÖRTER, DIE DU JETZT LERNST

DOM / DOM

Der Bauplan der Seite, den der Browser aus dem HTML macht.

Alltag: wie der Grundriss eines Hauses.

document

Element / element

Ein Teil der Seite: Absatz, Button, Bild.

Alltag: wie ein Möbelstück im Haus.

<p>…</p>

querySelector / querySelector

Die Suchfunktion: Findet ein Element per CSS-Auswahl.

Alltag: wie „Zeig mir den roten Stuhl im Wohnzimmer."

document.querySelector("#titel")

textContent / textContent

Der Text, der IN einem Element steht.

Alltag: der Zettel, der am Kühlschrank klebt.

el.textContent = "Neu!";

Die Seite lesen: querySelector

JavaScript kann nichts ändern, bevor es das Element gefunden hat. Die Suche ist der erste Schritt jedes DOM-Programms.

document.querySelector nimmt CSS-Selektoren (#id, .klasse, element) und liefert das erste Treffer-Element — oder null, wenn nichts passt.

Typische Fehler

Punkt bei Klassen vergessen

querySelector("karte") sucht ein <karte>-ELEMENT. Klassen brauchen den Punkt: ".karte".

Groß-/Kleinschreibung in der ID

#Titel findet id="titel" nicht. IDs sind case-sensitiv — exakt abtippen.

„querySelector liefert alle"

Nein — nur das ERSTE Element. Für alle Treffer gibt es querySelectorAll (Ausblick, kommt später).

null nicht prüfen

Wenn nichts gefunden wird, kommt null zurück — der Zugriff darauf wirft einen Fehler. Immer prüfen!

Profi-Tipp

Devtools öffnen, $0 und document.querySelector ausprobieren — die Konsole ist dein DOM-Labor.

Die Seite verändern: textContent & classList

Lesen war der Anfang. Jetzt wird geschrieben: Text ändern, Elemente ein- und ausblenden, Farben per Klasse umschalten.

textContent setzt Text — sicher, ohne HTML-Parsing. classList mit add/remove/toggle schaltet Zustände per Klasse.

Typische Fehler

innerHTML für reinen Text

textContent ist sicherer — es parst kein HTML. Nur wenn du wirklich HTML einfügen willst (und es vertraust), innerHTML.

classList falsch zugewiesen

karte.classList = "aktiv" überschreibt die ganze Liste — richtig: classList.add("aktiv").

Klasse ohne CSS

Die Klasse „aktiv" muss im Stylesheet eine Regel haben — sonst passiert sichtbar nichts.

Kinder zerstört

textContent ersetzt ALLES im Element — vorhandene Kinder-Elemente sind danach weg.

Profi-Tipp

Zustände per Klasse steuern, nicht per style-Attribut: .aktiv { … } im CSS — JavaScript schaltet nur um, das Design bleibt im Stylesheet.

DIDAKTISCHE PAUSE

Das DOM-Prinzip ist über 20 Jahre alt — und es ist heute noch DAS Fundament jeder Website, die du benutzt. Wer das DOM versteht, versteht, wie das Web WIRKLICH funktioniert.

Elemente erzeugen und einfügen

Bisher haben wir bestanden umgebaut. Jetzt bauen wir NEUES: Listeneinträge, Karten, ganze Bereiche — zur Laufzeit.

Das Muster heißt „bauen und anhängen": Erst mit createElement das Element fertig machen, Inhalt füllen — dann mit append ans Ende oder prepend an den Anfang einfügen.

Typische Fehler

append vergessen

Das Element existiert dann nur im Gedächtnis — sichtbar wird es erst durch append/prepend.

„#li" im createElement

createElement("#li") denkt an einen Selektor — falsch. Es braucht den reinen Tag-Namen: "li".

Reihenfolge durcheinander

Text vor dem Anhängen setzen oder danach — beides ok. Durcheinander bringt es nur, wer den Überblick verliert.

Eltern-Element null

Wenn querySelector nichts findet, ist liste null — append darauf wirft einen Fehler.

Profi-Tipp

Das Muster heißt „bauen und anhängen": Erst das Element fertig machen, dann einfügen. So bleibt dein Code lesbar.

Demo: Interaktive Einkaufsliste (erste echte App)

Suche, verändern, erzeugen — alles zusammen ergibt deine erste echte App: Eingabe, Button, Liste. Kapitel 10 macht sie noch reaktionsschneller.

Eingabefeld + Button → neuer Eintrag in der Liste. Eintrag anklickbar zum Abhaken (classList.toggle). Events kommen erst in Kapitel 10 dran — hier siehst sie nur in Aktion.

Interaktive Einkaufsliste

  • Brot

Tippe etwas ein und klicke auf einen Eintrag — er wird abgehakt (classList.toggle in Aktion).

Typische Fehler

Input-Wert vergessen

Der Text steckt in input.value — ohne ihn auszulesen, hängst du Leeres an.

Button reagiert nicht

Ohne Events passiert bei Klicks nichts. Wie ein Klick eine Funktion auslöst, erklärt Kapitel 10 (addEventListener).

Leere Einträge

Leere Eingabe nicht prüfen → die Liste voller Leerzeilen. Kurz value.trim() abfragen.

Falsches Eltern-Element

append auf den falschen Container und der Eintrag taucht an der falschen Stelle auf — Ziel immer per querySelector holen.

Profi-Tipp

Diese Demo ist dein Blueprint für das Abschlussprojekt: Eingabe → Verarbeitung → Anzeige. Alles, was du ab jetzt baust, folgt diesem Muster.

Zusammenfassung

  • DOM = Bauplan der Seite; document ist der Eingang.
  • querySelector findet per CSS-Selektor — null prüfen!
  • textContent für Text, classList für Zustände.
  • createElement + append bauen neue Teile.
  • Eingabe → Verarbeitung → Anzeige ist das Grundmuster jeder App.
