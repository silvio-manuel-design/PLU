Chapter 02

Variables & Data Types

Remember what your program knows: name values, store them, and read them correctly.

FIRST, LET'S UNDERSTAND

You have a locker at school. Your name is on it. You put something inside. Later you take it out again.

Your neighbour has his own locker. His name is on it. Your things and his things never mix.

That is a variable: a named place where the program keeps something. The name belongs to the place. The contents can change.

WORDS YOU'RE LEARNING NOW

Variable / Variable

A named place in the program’s memory.

Everyday: like your locker with a name tag.

let points = 0;

Value / Wert

What is currently inside the variable.

Everyday: whatever sits in your locker today.

points = 10;

Text (string) / text (string)

A value made of letters. Stands in quotes.

Everyday: like a note with a message.

let name = "Ada";

Number / Zahl

A value you can calculate with.

Everyday: like your account balance.

Declaring variables: let & const

A program without variables is a calculator without a memory key: it can't hold on to anything. Variables give values a name — and names are the most important tool in programming.

A variable is a named storage slot. Use let for values that change; const for values that stay constant. You declare with a keyword and assign with = — read it as „gets".

Remember: = is not an equation, it's a command: „take what's on the right and put it into the name on the left."

Points counter

0

Exactly this happens in your script: a variable you can re-assign on every click.

Typical mistakes

„= is an equals sign"

Wrong — it is an assignment. Say „points gets 10", not „points equals 10". The direction matters.

Declaring without a keyword

points = 10; without let/const creates an implicitly global variable — an error in strict mode, a ticking time bomb otherwise.

Misunderstanding const

With objects and arrays the contents can still change — only the reference is fixed. const list = [] may be filled, not reassigned.

Names with spaces & special characters

let my points or umlauts/special characters in names cause errors or pain. Rule: lower case, digits, underscores — and speaking names.

Pro tip

Use const first. Only switch to let when a line really must be reassigned — that prevents half of the chapter-03 mistakes.

Knowing data types: string, number, boolean, undefined

JavaScript automatically sorts every value into a type. If you don't know the types, you'll be surprised why '7' + 3 suddenly gives '73'.

The core types: string (text in quotes), number (integers and decimals), boolean (true/false) and undefined (nothing assigned yet). typeof checks the type of a value.

Typical mistakes

Mixed quotes

"Hello' breaks: the start and end of a string must use the same quote type — both " or both '.

"7" + 3 = "73"

A string plus a number produces concatenation, not arithmetic. JavaScript only calculates when both sides are numbers — convert first.

Comma instead of dot

7,5 is not a decimal in JavaScript — it creates an unexpected value. Decimals use a dot: 7.5.

Confusing undefined with null

undefined means: never assigned. null means: deliberately set empty. Two different statements, two different values.

Pro tip

Decimals: 0.1 + 0.2 === 0.3 is false (binary rounding). For money, calculate in cents — 199 + 1 instead of 1.99 + 0.01.

TEACHING BREAK

Variables aren't just a computer thing: your phone stores your PIN as a variable, your browser your password. The catch: a program forgets EVERYTHING when it ends — that's what databases are for (summer semester: backend).

Reading input with prompt()

So far we write values into the code ourselves. Programs only come alive when the USER enters values.

prompt("What's your name?") opens an input box and returns the entered text — always as a string, even for numbers! If you want to calculate, convert with Number().

Greeting demo

prompt() always returns a string — even if you type a number.

Typical mistakes

Calculating with prompt() directly

prompt("Age?") + 1 gives "161" instead of 17: the string is appended, not added. Run Number() first, then calculate.

Ignoring cancel

If someone clicks „Cancel", prompt() returns null. If you don't check for it, you'll later calculate with null and wonder why.

Asking for sensitive data

prompt() shows text in plain sight and stores nothing safely — never use it for passwords or private data. Learning purposes only.

Overlooking NaN

Number("abc") gives NaN — and (confusingly) NaN === NaN is false. Check with isNaN(value).

Pro tip

NaN means „Not a Number" — yet it IS a number type. JavaScript is full of such surprises; typeof NaN === 'number'.

Template literals & building output

Gluing strings together with + becomes unreadable with longer texts. Template literals are the modern standard.

Instead of quotes you use backticks. Inside ${'{'}…} you drop values, variables and even calculations directly into the text.

Typical mistakes

Plain quotes with ${}

"Hello ${name}" with straight quotes replaces nothing — ${} only works inside backticks.

Can't find the backtick key

On a German keyboard it sits left of Backspace, below Esc — often only visible after pressing space. (`´ ≠ `!)

Nested quotes

Without template literals "He said "Hello"" collides. Backticks solve it elegantly: `He said "Hello"`.

Forgetting ${}

`Grade: points` prints „Grade: points" literally — without ${} everything is text. The braces are the placeholder command.

Pro tip

Template literals can even calculate: `${'{'}price * 1.2} €` — arithmetic right inside the text. For anything complex, use a variable first.

Summary

  • Variables = named storage slots: let for changeable, const for fixed.
  • = assigns, it is NOT an equals sign.
  • The core types: string, number, boolean, undefined — typeof checks them.
  • prompt always returns a string → use Number() before calculating.
  • Template literals (backticks + ${}) build readable texts.
