FIRST, LET'S UNDERSTAND

You sit at the table. The doorbell rings. You get up and open the door. You react to an event.

Websites can do that too: a click is an event. A key press is an event. Your program says: “When click — do this.”

That turns your page from a poster into a conversation.

WORDS YOU'RE LEARNING NOW

Event / Ereignis

Something that happens on the page: click, key, input.

Everyday: like the doorbell.

click

addEventListener / addEventListener

The „on-watch" function: registers code for an event.

Everyday: like „I'll react as soon as it rings."

btn.addEventListener("click", …)

Callback / Callback

A function that gets called later — when the event fires.

Everyday: like you getting up when it rings.

function react() { … }

Event object / Event-Objekt

A folder with info about the event: which key, which element.

Everyday: like looking through the peephole.

event.target

Typical mistakes

Listener on the wrong element

If nothing happens, querySelector probably returned null — check the selector before blaming the listener.

„Click" instead of „click"

Event names are lowercase: "click", not "Click". Wrong case never fires.

Calling the callback immediately

addEventListener("click", react()) runs the function NOW and registers its result. Correct: pass react without parentheses.

Script before the HTML

If the script runs before the element, querySelector finds nothing. Script with defer in head or at the end of body — see chapter 01.

Pro tip

These three lines appear in millions of websites — element, listen, react. It's the foundation of interaction.

Reading input: input events and values

Clicks alone are boring — programs want to KNOW what the user typed.

The input event fires on EVERY change in the field. You read the value with element.value — and the event object tells you which field is meant via event.target.

Typical mistakes

textContent instead of value

For input fields the text lives in .value, not textContent — that holds for the field itself.

input vs. change

input fires on every keystroke, change only after leaving the field. For live feedback: input.

Forgetting the event parameter

Without the parameter function (event) there is no event.target — the classic copy slip.

Not checking for empty

Whoever prints „Hello, !" forgot the empty case — check briefly and set a default.

Pro tip

The pattern ‚input → event → output' connects chapter 02 (values), 09 (DOM) and 10 (events) — you're in the heart of the course.

TEACHING BREAK

Event-driven programs don't run top to bottom like a book. They WAIT. That feels strange at first — but that is exactly how your phone works: nothing happens until something happens.

State and multiple events: the counter app

Real apps remember things between clicks. A counter app is the smallest example of that.

The state variable lives OUTSIDE the listeners — the events change it, the DOM shows it. Plus and minus buttons share the same state.

Typical mistakes

Looking for state in the DOM

„Read the display, add 1, write back" goes wrong — the display is not a database. The variable counts, the DOM shows.

Everything in one listener

Two listeners with the same logic? Build a shared function and register it twice — don't copy-paste.

Forgetting counter++

Only display.textContent = counter shows the same value again and again — only ++ changes the state.

Forgetting reset

Every counter app needs a way back to 0 — it saves you many clicks while testing.

Pro tip

Rule of thumb: data in variables, display in the DOM. Never use the display as the only truth.

Keyboard & more events: reaction game

Clicks are just one event type. The keyboard opens up a whole playground: arrow keys, Enter, letters.

keydown fires on every key, event.key returns the key name ("Enter", "ArrowLeft", …). You check in the callback what should happen — and build games with it.

Reaction test

As soon as the field turns green: click. We measure the time in milliseconds — state + event + display in pure form.

Typical mistakes

keyCode instead of key

event.keyCode is old and deprecated — use event.key with the key name.

Wrong key names

"enter" doesn't work — the name is "Enter" (case-sensitive). Arrow keys: "ArrowLeft" etc.

Listener on the wrong element

Global keys (game control) belong on document, field input on the field.

setTimeout vs. setInterval

setTimeout = once after X ms, setInterval = over and over. The reaction test needs setTimeout.

Pro tip

Your final project (highscore game) builds on exactly this: state + events + display. You already have everything.
