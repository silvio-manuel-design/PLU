Functions: Reusable Code

Write it once, use it everywhere: think in building blocks.

FIRST, LET'S UNDERSTAND

You cook pasta. You know how: boil water, add salt, add pasta, drain. You don't rethink it every time. You can do it — you can even explain it to a friend.

A function is such a memory for your program: written once, used as often as you like. You give it something (a pack of pasta), it hands something back (a plate of pasta).

WORDS YOU'RE LEARNING NOW

Function / Funktion

A named building block of code you can reuse.

Everyday: like the recipe for pasta.

function greet() { … }

Parameter / Parameter

The value the function receives.

Everyday: the pack of pasta you put into the machine.

function greet(name) { … }

Return / Rückgabe

The result the function delivers.

Everyday: the finished plate.

return "Hello!";

Call / Aufruf

Actually using the function.

Everyday: „Now I'm cooking the pasta."

greet("Ada");

Declaring and calling functions

So far your code ran once through, line by line. Functions change that: code waits for its mission instead of running immediately.

You declare with function name() { … } and call with name(). The code in the body only runs ON CALL — the declaration merely prepares it.

Typical mistakes

Declared, never called

The most common beginner question: „Why does nothing happen?" — because greet() appears nowhere. Only the call starts the code.

Forgetting parentheses on the call

greet without () is the function ITSELF (as a value), not a call. The parentheses are the start button.

Duplicate names

Two functions with the same name: the second overwrites the first. Names should be unique and speaking.

„Functions must return something"

Not required. Functions may also just DO something (show, change) — return is an option, not a duty.

Pro tip

Function names are verbs: greet, calculate, show. Reading a verb, you instantly know what happens.

Parameters: inputs make functions flexible

A function without parameters is a recipe for exactly one dish. With parameters it becomes a kitchen machine: put in whatever you have.

Parameters are placeholders in the declaration's parentheses. On the call they get filled with real values — several separated by commas.

Typical mistakes

Swapped order

function divide(a, b) with divide(2, 10) divides 2 by 10 — the order of arguments matters.

Too few arguments

sum(3) gives NaN — missing parameters are undefined. The count must match.

Shadowing confusion

Parameter named like an outside variable? Inside the function only the parameter counts — confusing when reading. Keep names unique.

„Parameters are important variables"

No — they're just placeholders for the call. They don't exist outside.

Pro tip

Parameters are like the fields of a form: the function defines WHAT it needs — the caller fills them in.

TEACHING BREAK

Functions are teamwork in miniature: your code says “take care of this", the function answers “done, here is the result." Good code is a well-run conversation.

return: giving results back

So far your functions show something. They become powerful only when they RETURN results — that's what lets you keep calculating.

return ends the function and hands a value back to the caller. Nothing comes after. The returned value is a completely normal value: assign it, calculate with it, print it.

Typical mistakes

Confusing console.log with return

Showing is not returning. console.log shows you something, return gives your program something — two different worlds.

Code after return

return ends the function IMMEDIATELY. Everything after it is unreachable — dead code that never runs.

Forgetting return

A function without return gives back undefined — you can't keep calculating with that.

Missing return paths

With if/else every branch needs its return — otherwise one path goes back with undefined.

Pro tip

console.log is for humans, return is for your program. Pro rule: think return first, display second.

Composing small functions

Big programs are not long functions. They are many small, clear functions working together.

The pattern: functions call other functions. In the example, showGrade combines with the little helper gradeAsText. The arrow function here is for READING only — you'll learn to write it yourself later.

Typical mistakes

One function for everything

The 100-line „mega function" can be read by nobody — not even you in three weeks. Cut it small.

Writing arrow functions right away

First master the function pattern, then the short form. Starting with arrows tangles you in parentheses.

Not spotting a return as argument

showGrade(gradeAsText(2)): the inner call computes first, then hands over. Read from the inside out.

Too many levels at once

Four levels of nested calls overwhelm at first — build layer by layer and test each one separately.

Pro tip

One function = one job. If you see two jobs, build two functions. That's not extra work — it's relief.

Check: can you do this yet?

Each function has one job, the result travels on via return.

Summary

  • Function = named, reusable building block; body only runs on call.
  • Parameters = inputs, return = output.
  • console.log shows, return delivers.
  • Small functions call each other — that's how programs grow.
  • One function, one job.
