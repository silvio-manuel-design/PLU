FIRST, LET'S UNDERSTAND

Your HTML builds a house: walls, doors, windows. So far the house stood empty and still — as soon as the browser finished building.

The DOM is the blueprint of that house, made by your HTML. And JavaScript can change the plan while you watch: colour a window, open a door, add a room.

Reading the page: querySelector

JavaScript can't change anything before it finds the element. The search is the first step of every DOM program.

document.querySelector takes CSS selectors (#id, .class, element) and returns the first matching element — or null when nothing matches.

Typical mistakes

Forgetting the dot for classes

querySelector("card") looks for a <card> ELEMENT. Classes need the dot: ".card".

Case-sensitivity in the ID

#Title won't find id="title". IDs are case-sensitive — type them exactly.

„querySelector returns all"

No — only the FIRST element. For all matches there's querySelectorAll (preview, coming later).

Not checking for null

When nothing is found, null comes back — accessing it throws an error. Always check!

Pro tip

Open the DevTools and try $0 and document.querySelector — the console is your DOM lab.

Changing the page: textContent & classList

Reading was the start. Now we write: change text, show and hide elements, switch colours via a class.

textContent sets text — safe, no HTML parsing. classList with add/remove/toggle switches states via a class.

Typical mistakes

innerHTML for plain text

textContent is safer — it parses no HTML. Only use innerHTML when you really want HTML (and trust it).

Assigning classList wrongly

card.classList = "active" overwrites the whole list — correct: classList.add("active").

Class without CSS

The class „active" needs a rule in the stylesheet — otherwise nothing visible happens.

Destroyed children

textContent replaces EVERYTHING in the element — existing child elements are gone afterwards.

Pro tip

Control states via a class, not via the style attribute: .active { … } in the CSS — JavaScript only toggles, the design stays in the stylesheet.

TEACHING BREAK

The DOM principle is over 20 years old — and it is still THE foundation of every website you use. Whoever understands the DOM understands how the web REALLY works.

Creating and inserting elements

So far we remodelled what existed. Now we build NEW things: list items, cards, whole areas — at runtime.

The pattern is called „build then attach": first finish the element with createElement, fill in the content — then insert it with append (at the end) or prepend (at the start).

Typical mistakes

Forgetting append

The element then only exists in memory — it becomes visible only through append/prepend.

„#li" in createElement

createElement("#li") thinks of a selector — wrong. It needs the plain tag name: "li".

Mixing up the order

Setting text before or after attaching — both fine. It only gets messy when you lose track.

Parent element null

When querySelector finds nothing, list is null — append on it throws an error.

Pro tip

The pattern is called „build then attach": finish the element first, then insert it. That keeps your code readable.

Typical mistakes

Forgetting the input value

The text lives in input.value — without reading it, you append nothing.

Button doesn't react

Without events, clicks do nothing. How a click triggers a function is chapter 10 (addEventListener).

Empty entries

Not checking for empty input → a list full of blank lines. Just check value.trim().

Wrong parent element

append on the wrong container and the entry appears in the wrong place — always fetch the target via querySelector.

Pro tip

This demo is your blueprint for the final project: input → processing → display. Everything you build from now on follows this pattern.

AI Prompt Training

In this course you work with AI assistants throughout. Learn to write good prompts — that's the most important new skill.

Bad prompt „Build me something with the DOM."

Why is it bad?

No goal, no elements, no check — the result is arbitrary and stays unreviewed.

Good prompt „Have the AI generate a like-button component (click → counter + colour change). Check: does it use classList instead of style? does it find the element cleanly via querySelector?"

Why is it good?

Concrete component plus check criteria from the chapter (classList, querySelector) — you judge the AI solution professionally.
