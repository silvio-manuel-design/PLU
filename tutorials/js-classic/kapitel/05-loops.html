FIRST, LET'S UNDERSTAND

A song has a chorus. The chorus comes back again and again. Your brain knows: one more time. You sing it ten times — without thinking.

A loop is that for programs: repeat something until a goal is reached. You write the instruction once. The computer repeats it a thousand times. It never gets tired. It never complains.

That is the superpower of programming: repetition without fatigue.

WORDS YOU'RE LEARNING NOW

Loop / Schleife

Repeating an instruction until a goal is reached.

Everyday: like the chorus of a song.

for (let i = 1; i <= 5; i++)

Iteration / Durchlauf

A single repetition step.

Everyday: a single chorus.

`i` — in every pass

Counter / Zähler

A variable that counts the passes.

Everyday: like „time 1, time 2, time 3“ on a note.

let i = 1; i++

Infinite loop / Endlosschleife

A loop that never stops. Usually a slip.

Everyday: like a song without an end button.

condition never false

The for loop (counter-controlled)

Drawing 100 boxes? A human needs hours, a computer milliseconds. Loops are the reason programming pays off at all.

The for loop has three parts in its head: start (let i = 1), condition (i <= 5) and step (i++). Before every pass it checks: condition true? Then the block runs, then the step — round and round.

Typical mistakes

Infinite loop

If you forget the step (i++), the condition stays true forever — the browser freezes. Rescue: close the tab (then F5).

Off-by-one

<= instead of < makes the loop run once too often (or too rarely). Test with small numbers: 1 to 5 should run exactly 5 times.

Using i outside the loop

let i in the loop head only lives INSIDE the loop (block scope). If you need the counter afterwards, declare let i; before.

Changing the condition in the body

Anyone who resets the counter variable inside the block fights against the loop. Changes belong in the head's step part.

Pro tip

Count from 0 when iterating over arrays (coming in chapter 06) — from 1 only when it's really about ‚round 1..n'.

while & do...while (condition-controlled)

Sometimes you don't know HOW OFTEN in advance — only UNTIL WHEN: ‚keep playing until the level is done.'

while checks the condition BEFORE every pass — it can run 0 times. do...while checks AFTER the first pass — so it runs at least once.

Dice simulator

The simulator runs the while loop from the example — a different result every time.

Typical mistakes

Condition never reached

If the condition never becomes false: infinite loop. The tab hangs — F5 (after closing) is the rescue; saving beforehand was smart.

Forgetting the counter in the body

while (roll < 10) { console.log(roll); } without roll++ runs forever — the counter belongs inside the loop.

Misunderstanding do...while

„Check first, then run" is while. do...while runs FIRST — the check comes after. At least one pass is guaranteed.

Wrong loop type

Clear counting → for. Waiting for an event → while. If you maintain a counter in a while, ask yourself: wasn't that a for after all?

Pro tip

for = when you know the count; while = when you wait for an event. If you maintain the counter yourself in a while, consider whether it should be a for after all.

TEACHING BREAK

A computer runs a million repetitions without complaining — but it would never forget to increment the counter. Infinite loops are almost always human forgetfulness, not computer stubbornness.

break & continue (exit & skip)

Sometimes a loop must stop early (found it!) or skip a pass (invalid) — without ending the whole loop.

break leaves the loop entirely. continue jumps straight to the next pass. Both belong in your toolkit, used sparingly and deliberately — they change the „normal" flow.

Typical mistakes

break in nested loops

break only aborts the INNERMOST loop — the outer one keeps running. To stop everything you need a flag variable.

Unreadable continue at the top

Several continue conditions at the loop start confuse. Sometimes a clean if around the rest is more readable.

break instead of a proper condition

for (let i = 1; ; i++) { if (i > 5) break; } is possible, but the condition belongs in the head — break is for EARLY exits.

Forgetting continue → else chain

Anyone who shuns continue builds long else chains. A skipped pass is often the more honest structure.

Pro tip

break is your friend when searching: ‚run through the list until you find the element, then get out.' — saves cycles.

Nested loops & patterns

One box is boring — a 10×10 grid is a pattern. Nested loops build rows and columns.

The outer loop counts rows, the inner one columns. Total passes are the product of the limits — 3×5 makes 15 passes.

Pattern painter

The rectangle uses two full loops — the triangle's inner limit grows with the row.

Typical mistakes

Line break inside the inner loop

Calling console.log INSIDE the inner loop gives single stars instead of rows. Collect in a variable, print outside.

Same counter for both loops

for (let i... ) { for (let i... ) collides — every loop needs its own counter (e.g. row/col).

Swapped order

Which loop is outer, which inner? Rule of thumb: the OUTER one stands for what changes the LEAST often (rows), the INNER for the frequent (columns).

Ignoring O(n²)

100×100 are 10,000 passes — with nested loops effort grows quadratically. Big grids need patience (or smarter algorithms).

Pro tip

The 10×10 star pattern is the ‚Hello World' of nested loops — if you can do that, you can do arrays and later DOM grids.

Summary

  • for = count known; while = wait for an event.
  • The step (i++) belongs to the for — without it: infinite.
  • break = get out entirely; continue = skip one.
  • Nested loops build grids: rows × columns.
  • Off-by-one is the most common loop trap — test with small numbers!

AI Prompt Training

In this course you work with AI assistants throughout. Learn to write good prompts — that's the most important new skill.

Bad prompt „Make me a loop."

Why is it bad?

No task, no exit condition, no check criterion — the result is arbitrary and goes unreviewed.

Good prompt „Have the AI generate a small number guessing game (computer picks a number, user guesses, hints ‚higher/lower'). Review the AI: which loop type was chosen and why?"

Why is it good?

Concrete game plus targeted question about the loop choice — you learn to QUESTION decisions, not just accept them.
