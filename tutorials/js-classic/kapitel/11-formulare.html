Formulare & Validierung

Daten sauber einsammeln: Formulare bauen, prüfen und freundlich Fehler zeigen.

ERST MAL VERSTEHEN

Du kennst Formulare vom Amt und vom Arzt: Felder, die ausgefüllt werden müssen. Fehlt etwas, sagt dir jemand freundlich Bescheid — nicht unfreundlich.

Web-Formulare sind dasselbe: Felder zum Ausfüllen, Prüfung beim Absenden. Und weil du jetzt JavaScript kannst, baust du die Prüfung selbst.

WÖRTER, DIE DU JETZT LERNST

Formular / form

Eine Gruppe von Eingabefeldern mit Absende-Knopf.

Alltag: wie das Blatt beim Arzt.

<form>…</form>

Input / input

Ein einzelnes Eingabefeld (Text, E-Mail, Zahl …).

Alltag: eine Zeile auf dem Blatt.

<input type="email">

Validierung / validation

Das Prüfen der Eingaben vor dem Verarbeiten.

Alltag: wie der Blick der Sekretärin übers Formular.

feld.checkValidity()

submit / submit

Das Absende-Ereignis des Formulars.

Alltag: abgeben.

form.addEventListener("submit", …)

Formular und Inputs bauen

Das HTML-Formular ist das Gerüst: Ohne sauberes Gerüst kann JavaScript nichts retten.

Ein Formular bündelt Felder und den Absende-Knopf. Jedes Feld bekommt ein sichtbares Label — per for/id verbunden. Die Input-Typen (text, email, number, checkbox) geben dem Browser schon Hinweise.

Typische Fehler

Label ohne for/id-Verbindung

Ein Label ohne for (oder Feld nicht im Label) lässt Screenreader und Klick-auf-Label-Ziel im Stich.

type="email" vergessen

type="email" bringt Gratis-Prüfung und die passierte Tastatur auf dem Handy — nimm den passenden Typ.

Button ohne type

Ein Button im Formular ist automatisch type="submit" — hier gewollt, aber du solltest es wissen.

required vergessen

Pflichtfelder brauchen required — sonst merkt es erst dein JavaScript (oder niemand).

Profi-Tipp

Labels sind Pflicht — für Screenreader, für alle. Ein Feld ohne Label ist ein Formular mit Lücke.

Werte auslesen beim Absenden

Nach dem Klick auf ‚Anmelden' willst du die Werte — sauber und getrimmt.

Das submit-Event feuert beim Absenden. Mit event.preventDefault() verhinderst du das Neuladen der Seite — dann liest du die Werte aus und kürzt sie mit trim().

Typische Fehler

preventDefault vergessen

Die Seite lädt neu, alle Eingaben sind weg — der Klassiker. Erster Befehl im submit-Handler, immer.

value ohne trim()

" Ada " mit Leerzeichen zerstört Vergleiche und Speicherung — trim() gehört zum Auslesen dazu.

Falsche Selektoren

Die Felder haben id, nicht name — Selektor und Markup müssen zusammenpassen.

Absenden vor dem Listener

Wer das Formular testet, bevor das Script läuft, schickt es klassisch ab — erst lauschen, dann klicken.

Profi-Tipp

event.preventDefault() ist der wichtigste Einzeiler dieses Kapitels — ohne ihn startet dein Formular von vorne.

DIDAKTISCHE PAUSE

Das beste Formular der Welt ist das, das du nie bemerkst: wenige Felder, klare Worte, sofortige Hilfe. Jedes Feld, das du weglässt, macht das Formular besser.

Validierung: Erst HTML, dann JavaScript

Das HTML prüft schon automatisch (type, required). JavaScript ergänzt die Regeln, die HTML nicht kennt.

HTML5-Validierung deckt Format und Pflicht ab (required, type, minlength, pattern). Eigene Regeln — wie „gültige E-Mail" — schreibst du als Funktion in JavaScript.

Typische Fehler

„HTML-Validierung reicht"

Clientseitige Prüfung ist Komfort, kein Schutz — sie lässt sich umgehen (Kapitel 12!). Der Server muss prüfen.

Regeln doppelt und widersprüchlich

HTML sagt das eine, JS das andere — Nutzer verwirrt. Regeln an EINER Stelle definieren.

Fehler nur per alert()

Alert-Ketten sind der unfreundlichste Weg — Fehler gehören ans Feld (Schritt 4).

Validierung im Listener verstreut

Prüflogik gehört in kleine Funktionen (wie istGueltigeEmail) — testbar und wiederverwendbar.

Profi-Tipp

Regel: HTML validiert die Eingabe-HÜLLE (Format, Pflicht), JavaScript validiert die BEDEUTUNG (z. B. ‚Schülernummer beginnt mit 2 Ziffern').

Fehler freundlich zeigen (UX)

Jeder kennt Formulare, die einen anschreien. Freundliche, konkrete Fehlermeldungen sind der Unterschied zwischen frustrierten und fertigen Nutzern.

Die Meldung gehört ANS Feld (mit aria-live für Screenreader), der Fokus springt zum ersten Fehlerfeld, und nach der Korrektur verschwindet der Fehler wieder.

Anmeldeformular mit Live-Validierung

Absenden mit leerem oder falschem Feld: Der Fehler erscheint am Feld, Fokus springt dorthin. Korrigieren → Fehler verschwindet.

Typische Fehler

Alle Fehler als alert-Kette

Vier Alerts hintereinander sind pure Frustration — eine Meldung, am richtigen Feld.

Fehler nur farblich

Rot allein sagt nichts — immer mit Text (und aria-invalid für Screenreader).

aria-invalid vergessen

Screenreader merken den Fehler nur über das Attribut — setzen beim Fehler, entfernen bei der Korrektur.

Fehler verschwindet nie

Nach der Korrektur muss die Meldung weg — sonst glaubt der Nutzer, es stimmt immer noch nicht.

Profi-Tipp

Teste dein Formular mit den Augen eines genervten Menschen um 23 Uhr — dann weißt du, ob die Fehlermeldungen gut sind.

Check: Kannst du das schon?

HTML zuerst (kostenlos, sofort), JS danach (Bedeutung), Fehler immer am Feld.

Zusammenfassung

  • Formular = Gerüst, Labels = Pflicht.
  • submit abfangen, preventDefault, Werte trimmen.
  • HTML prüft Format und Pflicht, JS prüft Bedeutung.
  • Fehler freundlich am Feld zeigen, Fokus setzen.
  • Client-Validierung ist Komfort, nicht Sicherheit — Kap. 12 folgt.

Vertiefen
