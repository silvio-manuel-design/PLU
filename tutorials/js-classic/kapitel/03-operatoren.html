Kapitel 03

Operatoren

Rechnen, vergleichen, verknüpfen: die Werkzeuge, mit denen Werte zu Entscheidungen werden.

ERST MAL VERSTEHEN

In der Mathematik kennst du Zeichen: Plus, Minus, Mal, Geteilt. Sie verbinden zwei Dinge. 7 + 3 macht 10.

In JavaScript gibt es dieselben Zeichen — und ein paar mehr. Ein Zeichen, das zwei Werte verbindet, heißt Operator.

Die große Überraschung: Vergleiche sind auch Operatoren. „Ist 7 größer als 3?“ liefert wahr oder falsch. Damit kann das Programm entscheiden.

WÖRTER, DIE DU JETZT LERNST

Operator / operator

Ein Zeichen, das Werte verbindet oder vergleicht.

Alltag: wie Plus und Minus aus dem Matheheft.

7 + 3

Ausdruck / expression

Ein Stück Code, das ein Ergebnis liefert.

Alltag: wie eine kleine Rechnung.

punkte >= 50

wahr/falsch (boolean) / true/false

Das Ergebnis eines Vergleichs. Nur diese zwei Möglichkeiten.

Alltag: wie ja oder nein.

console.log(10 > 5); // true

Zuweisung / assignment

Etwas in eine Variable geben. Das Zeichen ist = .

Alltag: wie etwas in deinen Spind legen.

punkte = 10;

Rechnen mit Zahlen: + − * / % **

Operatoren sind die Verben von JavaScript. Alles, was mit Werten passiert, passiert durch sie.

Die Grundrechenarten kennst du — dazu kommen Modulo (Rest einer Division) und Potenz (**). Inkrement (runde++) ist die Kurzform für „um 1 erhöhen".

Playground

Probier es direkt aus — dein erster eigener Code läuft hier im Browser:

playground.js

Deine Aufgabe: Ergänze console.log(7 % 2) und console.log(8 % 2) — und erkläre, warum das Ergebnis genau 0 oder 1 ist.

Typische Fehler

„7 / 2 ist 3"

In JavaScript gibt 7 / 2 exakt 3.5 — es gibt keine Integer-Division wie in manchen anderen Sprachen. Kommazahlen sind normal.

„% ist Prozent"

Nein — % ist Modulo, der Rest einer Division. 7 % 2 ist 1, nicht 0.07. Für Prozente multiplizierst du mit 0.07.

a++ vs ++a ignorieren

a++ liefert den alten Wert, ++a den neuen — als Einzeiler fast immer egal, in verschachtelten Ausdrücken eine Falle. Erst erhöhen, dann verwenden: eigene Zeile.

Rundungsfehler bei Kommazahlen

0.1 + 0.2 ergibt 0.30000000000000004. Liegt am Binärsystem — bei Geld in Cent rechnen und Rundung bewusst einsetzen.

Profi-Tipp

Modulo ist der Geheimtipp: x % 2 === 0 prüft gerade Zahlen, x % 10 holt die Einerstelle — du wirst Modulo in jedem Spiel brauchen.

Vergleiche: === !== > < >= <=

Programme entscheiden. Vergleiche liefern true oder false — der Treibstoff jeder Bedingung (Kapitel 04).

=== ist der strikte Gleichheitsvergleich: Typ UND Wert müssen übereinstimmen. !== ist das Gegenteil. Das Ergebnis ist immer ein boolean.

Die ==-Falle: == wandelt Typen vor dem Vergleich um ("" == 0 ist true!). Das erzeugt unvorhersehbare Ergebnisse — deshalb gilt ab heute: nur === und !==.

Typische Fehler

= statt ===

if (punkte = 90) weist 90 zu und ist IMMER wahr — der klassischste Fehler überhaupt. Merkhilfe: „Vergleich = drei Striche, Zuweisung = einer."

== verwenden

„Loose equality" liefert Überraschungen: "" == 0 ist true, "0" == false auch. Niemand will das. === immer.

Strings lexikographisch verglichen

"10" < "9" ist true — Strings werden Buchstabe für Buchstabe verglichen („1" < „9"). Zahlen immer als Zahlen vergleichen.

NaN === NaN

Ist false — der einzige Wert, der nicht mit sich selbst identisch ist. Prüfen mit isNaN(x) oder Number.isNaN(x).

Profi-Tipp

ESLint regelt == automatisch weg. Ab heute: nur === und !== — ohne Ausnahme, ohne Diskussion.

DIDAKTISCHE PAUSE

Wusstest du, dass && und || in JavaScript keine reinen Booleans liefern, sondern einen der Operanden? "Ada" || "Gast" ergibt ‚Ada'. Logik als Wert — verrückt, aber nützlich.

Logik: && || !

Einzelne Vergleiche reichen selten. ‚Über 16 UND unter 65' — dafür brauchst du logische Verknüpfungen.

&& (UND) ist nur wahr, wenn beide Seiten wahr sind. || (ODER) ist wahr, wenn mindestens eine Seite wahr ist. ! (NICHT) kehrt um. JavaScript wertet von links nach rechts aus und bricht ab, sobald das Ergebnis feststeht (Kurzschluss).

Typische Fehler

&&/|| mit „und/oder" verwechseln

In Code sind es Symbole, keine Wörter: and oder or gibt es in JavaScript nicht — && und || schon.

Bedingungen nicht klammern

alter >= 16 && < 65 ist ein Fehler — die zweite Hälfte hat keine Variable. Vollständig: alter >= 16 && alter < 65.

!!x unverstanden

Doppeltes ! wandelt einen Wert in einen echten boolean um (!!"Ada" → true). Praktisch, aber erst sinnvoll, wenn du die Typumwandlung verstehst.

Kurzschluss überrascht

false && … bricht ab, true || … ebenfalls — der rechte Teil läuft dann GAR NICHT. Bei Funktionsaufrufen rechts kann das Nebenwirkungen verschlucken.

Profi-Tipp

|| ist auch der Standard-Fallback: const name = eingabe || 'Gast'; — wenn eingabe leer ist, greift der Fallback.

Zuweisungs-Operatoren: += -= *= /=

punkte = punkte + 10 schreibt man in echt nie. Die Kurzformen sind Standard in jedem Code, den du je lesen wirst.

+= -= *= /= %= rechnen rechts und weisen das Ergebnis direkt der linken Variable zu. Auch für Strings: += hängt Text an.

Typische Fehler

Richtung verwechseln

10 += punkte ist ein Syntaxfehler — die Variable muss links stehen, der Wert rechts: punkte += 10.

Rechnen ohne zuweisen

punkte + 10; berechnet 10 mehr, verwirft das Ergebnis aber sofort. Ohne punkte += 10 ändert sich nichts.

+= bei const

const x = 0; x += 1; wirft einen Fehler — const kann nicht neu zugewiesen werden, auch nicht per Kurzform. Dann muss es let sein.

Zahlen und Strings mischen

log += 5 hängt „5" als Text an, wenn log ein String ist. Typen im Blick behalten — siehe Kapitel 02.

Profi-Tipp

Counters in Spielen: treffer += 1 bzw. treffer++ — damit baust du das Highscore-System fürs Abschlussprojekt.

Check: Kannst du das schon?

Ein Vergleich liefert boolean, Modulo liefert den Rest — beide zusammen sind die Basis jeder Bedingung.

Zusammenfassung

  • Rechnen: + − * / % ** — / ergibt immer Kommazahlen.
  • Modulo = Rest, der Prüf-Allrounder.
  • Vergleiche liefern boolean — immer === statt ==.
  • && || ! verknüpfen Bedingungen; || ist auch der Fallback-Trick.
  • += & Co. sind die Kurzformen, ohne die kein Counter existiert.
