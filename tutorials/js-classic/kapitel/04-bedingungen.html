Bedingungen

Wenn das, dann jenes: Entscheidungen treffen lassen und Programme auf Situationen reagieren lassen.

ERST MAL VERSTEHEN

Du triffst den ganzen Tag Entscheidungen. Wenn es regnet, nimmst du einen Schirm. Wenn nicht, lässt du ihn zu Hause. Du prüfst die Welt. Dann handelst du.

Ein Programm kann das auch. Es prüft eine Bedingung. Dann führt es den einen Weg oder den anderen aus.

Das Wichtigste vorweg: Das Programm liest deine Bedingung. Es entscheidet nie selbst. Du gibst ihm die Regeln.

WÖRTER, DIE DU JETZT LERNST

Bedingung / condition

Eine Prüfung, die wahr oder falsch liefert.

Alltag: wie „Regnet es gerade?“

if (alter >= 16)

Verzweigung / branch

Der Punkt, an dem das Programm den Weg wählt.

Alltag: wie eine Weggabelung.

if … else …

Code-Block / code block

Mehrere Zeilen, die zusammen gehören. Steht in geschweiften Klammern.

Alltag: wie ein Arbeitsschritt aus mehreren Teilen.

{ … }

Entscheidung / decision

Das Ergebnis der Prüfung: dieser Weg oder jener.

Alltag: wie dein Schirm-Entscheid am Morgen.

alter >= 16 ? "ja" : "nein"

if/else — die Grundentscheidung

Bedingungen sind der Moment, in dem ein Skript vom Blatt Papier lebendig wird: Es reagiert unterschiedlich auf unterschiedliche Eingaben.

if prüft einen booleschen Ausdruck in Klammern. Ist er wahr, läuft der Block in {}, sonst der else-Zweig. Mit else if kettest du beliebig viele Fälle aneinander — der erste Treffer gewinnt.

Noten-Rechner

Genau die else-if-Kette aus dem Beispiel — als Demo zum Nachvollziehen.

Typische Fehler

Klammern nach if vergessen

if punkte >= 50 ohne runde Klammern ist ein Syntaxfehler. Die Bedingung steht IMMER in ( ).

Keine {} bei Einzeilern

Ohne geschweifte Klammern gilt nur die erste Zeile als Bedingungs-Körper. Spätere Erweiterungen landen dann unbeabsichtigt IMMER im Programm — immer {} setzen.

= statt === in der Bedingung

if (punkte = 90) weist 90 zu und ist immer wahr — der kapitalste Fehler. Vergleichen: ===.

Falsche Reihenfolge der Kette

Bei >=-Ketten muss der größte Wert zuerst kommen, sonst frisst ein früher Zweig die späteren. Absteigend bauen!

Profi-Tipp

Lies else-if-Ketten von oben nach unten wie ein Menü: der erste Treffer gewinnt, der Rest wird übersprungen.

Vergleiche & Logik kombinieren

Echte Bedingungen sind selten einfach: ‚Erwachsen UND Mitglied' oder ‚Wochenende ODER Feiertag'. Kap. 03 liefert die Bausteine — hier steckst du sie zusammen.

Kombiniere Vergleiche mit && und ||. Bei gemischten Bedingungen Klammern setzen — dann bleibt die Priorität klar und lesbar.

Typische Fehler

Klammern bei gemischten Bedingungen vergessen

a && b || c ist ohne Klammern uneindeutig — was zuerst? Schreib (a && b) || c und meine, was du meinst.

&& und || ungeklammert mischen

JavaScript wertet && vor || aus — ohne Klammern entsteht Logik, die du so nicht meintest. Klammern sind gratis, nutze sie.

Boolesche Variablen doppelt prüfen

if (elternDa === true) ist redundant — elternDa ist schon der Wert, den das if braucht: if (elternDa).

Umständlich negiert statt else

if (!eingeloggt) { … } UND if (eingeloggt) { … } daneben ist doppelt. Eine Seite reicht — die andere gehört in else.

Profi-Tipp

Eine Variable, die schon true/false ist, braucht keinen Vergleich mehr: if (eingeloggt) statt if (eingeloggt === true).

DIDAKTISCHE PAUSE

Dein Alltag ist voller Bedingungen: Wenn der Wecker klingelt, stehst du auf — sonst drehst du dich um. if/else haben dir das Denken abgeschaut, nicht umgekehrt.

switch für viele Fälle

Lange else-if-Ketten über denselben Wert werden unleserlich. switch ist die übersichtliche Alternative für 3+ Fälle.

switch vergleicht einen Wert gegen viele Fälle. break beendet einen Fall — ohne break laufen alle folgenden Fälle mit durch („fall-through"). default fängt alles Übrige ab.

Typische Fehler

break vergessen

Ohne break laufen alle Fälle AB DEM TREFFER durch — bei Schulnoten kriegst du „Sehr gut Gut Befriedigend" auf einmal.

case mit Bedingungen

case punkte >= 50: funktioniert nicht — switch vergleicht Werte mit ===, keine Bereiche. Für Bereiche: if/else.

default vergessen

Was passiert bei Wert 6? Ohne default: nichts — still und heimlich. Der Rest-Fall gehört immer abgedeckt.

switch für boolesche Bedingungen

switch (true)-Trickserei gibt es — aber boolesche Logik gehört in if/else. switch ist für feste Werte: Wochentage, Noten, Menüs.

Profi-Tipp

switch mit break zu vergessen ist die häufigste JS-Falle Nummer 1 in Zeugnis-Programmen — lies deinen Code immer laut beim Durchfallen-Fall.

Der ternäre Operator (kurze Entscheidungen)

Manchmal ist eine Entscheidung nur eine Zeile wert: Ein Wert oder der andere. Der ternäre Operator ? : ist die Kurzform.

bedingung ? wertWennWahr : wertWennFalsch — ideal für Zuweisungen und Template-Literals, wo ein if/else klobig wäre.

Typische Fehler

Mehrfach schachteln

a ? b : c ? d : e wird unleserlich. Eine Entscheidung = ein ternär; alles Komplexere gehört in if/else.

Für Nebenwirkungen missbrauchen

bedingung ? console.log(a) : console.log(b) ist machbar, aber unschön — ternär liefert WERTE, if/else macht Aktionen.

Den Doppelpunkt vergessen

alter >= 16 ? "Erwachsen" ohne : … ist ein Syntaxfehler — beide Zweige gehören zur Entscheidung.

Komplexe Bedingungen ohne Klammern

a && b ? x : y lässt den Leser raten — Klammern machen es eindeutig: (a && b) ? x : y.

Profi-Tipp

Ternär ist für EINE Entscheidung zwischen ZWEI Werten. Alles Komplexere gehört in if/else — kein Wettschreiben.

Check: Kannst du das schon?

switch für feste Werte, if für Bereiche — das ist die Trennlinie.

Zusammenfassung

  • if/else = Verzweigung; else-if-Ketten von groß nach klein bauen.
  • Die größte Falle: = statt === im if.
  • Mehrere Bedingungen: Klammern setzen, && und || bewusst einsetzen.
  • switch = übersichtlich für viele Fälle eines Werts, break nicht vergessen.
  • Ternär ? : für kurze Zwei-Wert-Wahlen, sonst if/else.

KI-Prompt-Training

Du arbeitest im Kurs grundsätzlich mit KI-Assistenten. Lern, gute Prompts zu schreiben — das ist die wichtigste neue Fähigkeit.

Schlechter Prompt „Schreib mir was mit if."

Warum schlecht?

Kein Ziel, kein Kontext, keine Prüfung — das Ergebnis ist Zufall, und du lernst nichts dabei.

Guter Prompt „Lass dir von der KI ein Ampel-Steuerungsscript erzeugen (rot/gelb/grün mit unterschiedlichen Wartezeiten). Prüfe: Sind die Bedingungen sauber getrennt? Wo würdest du switch statt if nehmen?"

Warum gut?

Konkretes Programm + gezielte Kontrollfragen: Du übst nicht nur das Schreiben, sondern das Prüfen — die wichtigere Hälfte.
