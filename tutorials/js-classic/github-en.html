You know the drill: essay.docx, essay_final.docx, essay_REALfinal.docx. In the end you don't know which version is new.

Git ends that chaos. Every state of your work gets a name and a date. You can go back anytime. You can continue on any device. And your teacher sees your work — without you uploading anything.

For students: set up your first submission

  1. 1

    Check your GitHub account

    are you signed in? Are you a member of the class organisation? (Your teacher invites you.)

  2. 2

    Connect VS Code

    extensions installed (see the VS Code page), install Git (git-scm.com), then in VS Code: account menu → „Sign in with GitHub".

  3. 3

    Create your repo from the template

    Your teacher sends you the link to the class template. On the template page → „Use this template" → „Create a new repository" → Owner: your account → name it by the course scheme, e.g. jsc-ch02-2a-17 → Private → Create. Important: the repo belongs to you — you are the owner, not your teacher. Then invite your teacher as a collaborator (step 8) so they can see your work.

  4. 4

    Clone

    Cloning means: a copy of the repo lands on your machine. On your repo, click the green „<> Code" button → HTTPS tab → copy the URL. In VS Code: Ctrl+Shift+P → „Git: Clone" → paste the URL → pick a location (e.g. Documents → web) → „Open". Check: the Explorer on the left shows the repo name with its files — including the README.md from the template.

  5. 5

    Work

    Open the files from the Explorer and solve the exercises — just like on the chapter pages, only in your own folder. Don't forget to save (Ctrl+S). Tip: commit between exercises (next step) — then every intermediate state is safe if something breaks.

  6. 6

    Commit

    A commit is a labelled intermediate state. Source Control panel (Ctrl+Shift+G): click + under „Changes" (staging) → write a message that says what you did („Ch02 exercise 1 solved") → click the tick to commit. The first time, VS Code asks for your name and email — enter your GitHub name and email, once. Check: the „Changes" list is empty and your state appears under „Commits".

  7. 7

    Push

    Committing only saves the state locally on your machine. Pushing uploads it to GitHub: click the arrow icon „Sync Changes" („Publish Branch" the first time) — done when the arrow stops spinning. Check: open your repo in the browser — your commit with its timestamp must be visible there. Only what is pushed can be seen by your teacher.

  8. 8

    Invite your teacher

    Repo → Settings → Collaborators → add your teacher. The submission is the link to the repo.

Typical mistakes

„Authentication failed"

Signed out or expired — sign in to GitHub again in VS Code (account menu → Sign in).

„Repository not found" when cloning

Check the URL — and you must accept the organisation invitation first.

„Commit doesn't work"

Set your name and email once (VS Code asks on the first commit) — then it runs.

„I pushed to the wrong repo"

No drama: ask your teacher, correct the state, commit again. That's what Git is for.

For teachers: set up GitHub in the classroom

  1. 1

    Account & organization

    Create a GitHub account — with your school or your private email address, whichever your school allows (or use an existing one) → profile menu → Organizations → New organization — it's free. Name it e.g. htl-web-2a. You become the classroom's administrator; invite students by username or email. Tip: let students work with numbers instead of real names — for their GitHub usernames too.

  2. 2

    Create & maintain the template repo

    New repo in the organization with the starter files: index.html, css/, js/, a README.md with the task, and a .gitignore. Repo → Settings → tick „Template repository". This template is the base of every submission — deliberately plain standard GitHub, no extra tools: once the template stands, there is nothing else to manage.

  3. 3

    Share the link & mandate a naming scheme

    Send the template link via your usual course channel (LMS, email, board) — one day before the first lesson, so signing up doesn't eat into class time. Mandate the naming scheme jsc-chXX-class-nr: unique, anonymous, sortable. You can find every submission via the org search — even with 30 repos.

  4. 4

    Plan the first lesson

    Schedule computer time: students follow the student guide above. Allow 20–30 minutes for the first clones and sign-ins — after that the workflow runs itself. Share the link to this page; the template link travels separately.

  5. 5

    Collect & review submissions

    Each student invites you as a collaborator (step 8 of the student guide) — you see all repos in the organization. Overview via org search: jsc-ch02 shows all submissions of the chapter. Who hasn't pushed, you can tell by the missing timestamp; for terminal triage, git status on the student's machine is enough. For advanced users: gh CLI (gh search repos).

  6. 6

    Give feedback

    In the student repo: one issue or a comment per commit — that keeps the feedback attached to the state it refers to. No correction commits directly on main; that would tangle the history.

  7. 7

    Update the course material

    When a task changes, update the template repo — the next class automatically starts from the new state. Old submissions stay untouched, because every student repo is an independent copy.

  8. 8

    Privacy quick check

    Private repos; no real names in repo names or usernames; no grades in repos; student accounts via the school email; reflections (.md) stay local on the devices. For minors: get parental consent for the online account — as with any course tool.

Typical mistakes

„Student has no account"

Sign up with the school mail, GitHub Student Pack optional — done in minutes.

„Too many single repos"

Naming scheme + org search instead of a dashboard — that's how you keep track even with 30 repos.

„Student doesn't push"

Terminal triage: git status shows what needs to be committed or pushed.

„Org limits"

The free plan covers private repos at classroom scale — no costs, no upgrade needed.
