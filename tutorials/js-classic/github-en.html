FIRST, LET'S UNDERSTAND

You know the drill: essay.docx, essay_final.docx, essay_REALfinal.docx. In the end you don't know which version is new.

Git ends that chaos. Every state of your work gets a name and a date. You can go back anytime. You can continue on any device. And your teacher sees your work — without you uploading anything.

For students: set up your first submission

  1. 1

    Check your GitHub account

    are you signed in? Are you a member of the class organisation? (Your teacher invites you.)

  2. 2

    Connect VS Code

    extensions installed (see the VS Code page), install Git (git-scm.com), then in VS Code: account menu → „Sign in with GitHub".

  3. 3

    Create a repo from the template

    Go to the class template (link from your teacher) → „Use this template" → „Create a new repository" → Owner: your account → Name: jsc-chXX-class-nr (e.g. jsc-ch02-2a-17) → Private → Create.

  4. 4

    Clone

    On your repo, click „Code" → copy the HTTPS URL → VS Code: Ctrl+Shift+P → „Git: Clone" → paste the URL → pick a folder.

  5. 5

    Work

    solve the exercises in the folder and save the files.

  6. 6

    Commit

    Source Control panel (Ctrl+Shift+G): stage your changes (+), write a message („Ch02 exercise 1 solved"), tick = commit.

  7. 7

    Push

    Click „Publish Branch" or the up arrow. Done — your state is on GitHub.

  8. 8

    Invite your teacher

    Repo → Settings → Collaborators → add your teacher. The submission is the link to the repo.

Typical mistakes

„Authentication failed"

Signed out or expired — sign in to GitHub again in VS Code (account menu → Sign in).

„Repository not found" when cloning

Check the URL — and you must accept the organisation invitation first.

„Commit doesn't work"

Set your name and email once (VS Code asks on the first commit) — then it runs.

„I pushed to the wrong repo"

No drama: ask your teacher, correct the state, commit again. That's what Git is for.

For teachers: set up GitHub in the classroom

  1. 1

    Organisation

    GitHub → Organizations → New (e.g. htl-web-2a). Invite students (username or email). Tip: let students work with numbers instead of real names.

  2. 2

    Template repo

    New repo in the org: starter files (index.html, css/, js/, README.md with the task, .gitignore). Settings → enable „Template repository".

  3. 3

    Naming scheme

    mandate jsc-chXX-class-nr: unique, anonymous, sortable.

  4. 4

    First lesson

    students follow the student guide (above). You help with the first clones.

  5. 5

    Overview

    search in the org: jsc-ch02 shows all submissions. For advanced users: gh CLI (gh search repos).

  6. 6

    Feedback

    in the student repo: an issue or a comment per commit. No correction commits directly on main.

  7. 7

    Privacy quick check

    private repos; no real names; no grades in repos; the reflection export (.md) stays local.

Typical mistakes

„Student has no account"

Sign up with the school mail, GitHub Student Pack optional — done in minutes.

„Too many single repos"

Naming scheme + org search instead of a dashboard — that's how you keep track even with 30 repos.

„Student doesn't push"

Terminal triage: git status shows what needs to be committed or pushed.

„Org limits"

The free plan covers private repos at classroom scale — no costs, no upgrade needed.
