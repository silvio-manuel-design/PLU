Deine Arbeit sicher speichern, versionieren und abgeben — mit dem Werkzeug echter Entwickler und dem Template deiner Klasse. Alles mit Standard-GitHub, ganz ohne Zusatz-Tools.

Zu GitHub (externer Link, öffnet neues Fenster)

ERST MAL VERSTEHEN

Du kennst das: referat.docx, referat_final.docx, referat_ECHTfinal.docx. Am Ende weißt du nicht mehr, welche Version die neueste ist.

Git beendet dieses Chaos. Jeder Stand deiner Arbeit bekommt einen Namen und ein Datum. Du kannst jederzeit zurück. Du kannst von jedem Gerät weiterarbeiten. Und deine Lehrkraft sieht deine Arbeit — ohne dass du etwas hochladen musst.

Für Schüler: Erste Abgabe einrichten

  1. 1

    GitHub-Account prüfen

    bist du eingeloggt? Bist du Mitglied der Klassen-Organisation? (Deine Lehrkraft lädt dich ein.)

  2. 2

    VS Code verbinden

    Extensions installiert (siehe VS-Code-Seite), Git installieren (git-scm.com), dann in VS Code: Account-Menü → „Sign in with GitHub".

  3. 3

    Dein Repo aus dem Template erstellen

    Deine Lehrkraft schickt dir den Link zum Template der Klasse. Auf der Template-Seite → „Use this template" → „Create a new repository" → Owner: dein Account → Name nach dem Kurs-Schema, z. B. jsc-kap02-2a-17 → Private → Create. Wichtig: Das Repo gehört dir — du bist Ownerin oder Owner, nicht die Lehrkraft. Danach lädst du deine Lehrkraft als Collaborator ein (Schritt 8), damit sie deine Arbeit sieht.

  4. 4

    Klonen

    Klonen heißt: Eine Kopie des Repos landet auf deinem Rechner. Auf deinem Repo die grüne Schaltfläche „<> Code" → Reiter HTTPS → URL kopieren. In VS Code: Strg+Shift+P → „Git: Clone" → URL einfügen → Speicherort wählen (z. B. Dokumente → web) → „Open". Kontrolle: Im Explorer links steht der Repo-Name samt Dateien — darunter die README.md aus dem Template.

  5. 5

    Arbeiten

    Öffne die Dateien aus dem Explorer und löse die Übungen — genau wie auf den Kapitelseiten, nur in deinem eigenen Ordner. Speichern nicht vergessen (Strg+S). Tipp: Mach zwischen den Aufgaben einmal einen Commit (nächster Schritt) — dann ist jeder Zwischenstand gerettet, falls etwas kaputt geht.

  6. 6

    Committen

    Ein Commit ist ein beschrifteter Zwischenstand. Quellcode-Panel (Strg+Shift+G): unter „Änderungen" auf + klicken → oben eine Nachricht schreiben, die sagt, was du getan hast („Kap02 Übung 1 gelöst") → Häkchen klicken = Commit. Beim ersten Mal fragt VS Code nach Name und E-Mail — GitHub-Name und deine Mail eintragen, einmalig. Kontrolle: Die Liste „Änderungen" ist leer und dein Stand steht unter „Commits".

  7. 7

    Pushen

    Committen rettet den Stand nur lokal auf deinem Rechner. Pushen überträgt ihn zu GitHub: das Pfeil-Symbol „Sync Changes" klicken (beim ersten Mal „Publish Branch") — fertig, wenn der Pfeil stillsteht. Kontrolle: Öffne dein Repo im Browser — dein Commit mit Zeitstempel muss dort sichtbar sein. Nur was gepusht ist, kann deine Lehrkraft sehen.

  8. 8

    Lehrkraft einladen

    Repo → Settings → Collaborators → Lehrkraft hinzufügen. Die Abgabe ist der Link zum Repo.

Typische Fehler

„Authentication failed"

Abgemeldet oder abgelaufen — in VS Code neu mit GitHub anmelden (Account-Menü → Sign in).

„Repository not found" beim Klonen

URL prüfen — und die Einladung zur Organisation muss zuerst angenommen sein.

„Commit geht nicht"

Einmalig Namen und E-Mail setzen (VS Code fragt beim ersten Commit danach) — dann läuft es.

„Ich hab ins falsche Repo gepusht"

Kein Drama: Lehrkraft fragen, Stand korrigieren, neu committen. Genau dafür ist Git da.

Für Lehrkräfte: GitHub im Unterricht einrichten

  1. 1

    Account & Organisation

    Lege einen GitHub-Account an — mit deiner Schul- oder deiner privaten E-Mail-Adresse, wie es deine Schule erlaubt (oder einen vorhandenen Account nutzen) → Profilmenü → Organizations → New organization — das ist kostenlos. Name z. B. htl-web-2a. Du bist damit Administratorin oder Administrator des Klassenraums; Schüler:innen ladest du über Username oder E-Mail ein. Tipp: Schüler:innen arbeiten mit Nummern statt Klarnamen — auch bei den GitHub-Usernamen.

  2. 2

    Template-Repo anlegen & pflegen

    Neues Repo in der Organisation mit den Starter-Dateien: index.html, css/, js/, README.md mit der Aufgabenstellung, .gitignore. Repo → Settings → Haken bei „Template repository". Dieses Template ist der Grundstock jeder Abgabe — bewusst mit Standard-GitHub, ganz ohne Zusatz-Tools: Wenn das Template steht, brauchst du nichts weiter zu verwalten.

  3. 3

    Link verteilen & Namensschema vorgeben

    Schicke den Link zum Template über deinen üblichen Kurskanal (LMS, E-Mail, Tafelbild) — einen Tag vor der ersten Einheit, damit die Registrierung nicht in der Stunde passiert. Das Namensschema jsc-kapXX-klasse-nr verbindlich vorgeben: eindeutig, anonym, sortierbar. Damit findest du jede Abgabe über die Org-Suche — auch bei 30 Repos.

  4. 4

    Erste Einheit planen

    Rechnerzeit einplanen: Schüler:innen folgen der Schüler-Anleitung oben. Rechne mit 20–30 Minuten für die ersten Clones und Anmeldungen — danach läuft der Workflow. Verteile den Link zu dieser Seite; der Template-Link reist separat.

  5. 5

    Abgaben sammeln & prüfen

    Jede Schülerin und jeder Schüler lädt dich als Collaborator ein (Schritt 8 der Schüler-Anleitung) — du siehst alle Repos in der Organisation. Überblick per Org-Suche: jsc-kap02 zeigt alle Abgaben des Kapitels. Wer nicht pusht, siehst du am fehlenden Zeitstempel; für die Terminal-Triage genügt git status auf dem Rechner der Person. Für Fortgeschrittene: gh CLI (gh search repos).

  6. 6

    Feedback geben

    Im Schüler-Repo: ein Issue oder ein Kommentar pro Commit — so bleibt das Feedback am Stand, auf den es sich bezieht. Keine Korrektur-Commits direkt auf main, das würde die Geschichte durcheinanderbringen.

  7. 7

    Kursmaterial aktualisieren

    Ändert sich eine Aufgabenstellung, aktualisiere das Template-Repo — die nächste Klasse startet automatisch mit dem neuen Stand. Alte Abgaben bleiben unberührt, denn jedes Schüler-Repo ist eine eigenständige Kopie.

  8. 8

    Datenschutz-Kurzcheck

    Private Repos; keine Klarnamen in Repo-Namen und Usernames; keine Noten in Repos; Schüler:innen-Accounts über die Schülermail; Reflexionen (.md) bleiben lokal auf den Geräten. Bei Minderjährigen: Einverständnis der Eltern für den Online-Account einholen — wie bei jedem Kurs-Tool.

Typische Fehler

„Schüler hat keinen Account"

Anmeldung mit Schülermail, GitHub Student Pack optional — in Minuten erledigt.

„Zu viele Einzel-Repos"

Namensschema + Org-Suche statt Dashboard — so behältst du auch bei 30 Repos den Überblick.

„Schüler pusht nicht"

Terminal-Triage: git status zeigt, was committet oder gepusht werden muss.

„Org-Grenzen"

Der Free-Plan reicht für private Repos im Unterrichtsmaßstab — keine Kosten, kein Upgrade nötig.
