ERST MAL VERSTEHEN

Du kennst das: referat.docx, referat_final.docx, referat_ECHTfinal.docx. Am Ende weißt du nicht mehr, welche Version die neueste ist.

Git beendet dieses Chaos. Jeder Stand deiner Arbeit bekommt einen Namen und ein Datum. Du kannst jederzeit zurück. Du kannst von jedem Gerät weiterarbeiten. Und deine Lehrkraft sieht deine Arbeit — ohne dass du etwas hochladen musst.

Für Schüler: Erste Abgabe einrichten

  1. GitHub-Account prüfen — bist du eingeloggt? Bist du Mitglied der Klassen-Organisation? (Deine Lehrkraft lädt dich ein.)
  2. VS Code verbinden — Extensions installiert (siehe VS-Code-Seite), Git installieren (git-scm.com), dann in VS Code: Account-Menü → „Sign in with GitHub".
  3. Repo aus dem Template erstellen — Zum Template der Klasse (Link von der Lehrkraft) → „Use this template" → „Create a new repository" → Owner: dein Account → Name: jsc-kapXX-klasse-nr (z. B. jsc-kap02-2a-17) → Private → Create.
  4. Klonen — Auf deinem Repo „Code" → HTTPS-URL kopieren → VS Code: Strg+Shift+P → „Git: Clone" → URL einfügen → Ordner wählen.
  5. Arbeiten — Löse die Übungen im Ordner und speichere die Dateien.
  6. Committen — Quellcode-Panel (Strg+Shift+G): Änderungen stagen (+), Nachricht schreiben („Kap02 Übung 1 gelöst"), Häkchen = Commit.
  7. Pushen — „Publish Branch" bzw. den Pfeil nach oben klicken. Fertig — dein Stand ist auf GitHub.
  8. Lehrkraft einladen — Repo → Settings → Collaborators → Lehrkraft hinzufügen. Die Abgabe ist der Link zum Repo.

Typische Fehler

„Authentication failed"

Abgemeldet oder abgelaufen — in VS Code neu mit GitHub anmelden (Account-Menü → Sign in).

„Repository not found" beim Klonen

URL prüfen — und die Einladung zur Organisation muss zuerst angenommen sein.

„Commit geht nicht"

Einmalig Namen und E-Mail setzen (VS Code fragt beim ersten Commit danach) — dann läuft es.

„Ich hab ins falsche Repo gepusht"

Kein Drama: Lehrkraft fragen, Stand korrigieren, neu committen. Genau dafür ist Git da.

Für Lehrkräfte: GitHub im Unterricht einrichten

  1. Organisation — GitHub → Organizations → New (z. B. htl-web-2a). Schüler einladen (Username oder E-Mail). Tipp: Schüler arbeiten mit Nummern statt Klarnamen.
  2. Template-Repo — Neues Repo in der Org: Starter-Dateien (index.html, css/, js/, README.md mit Aufgabenstellung, .gitignore). Settings → „Template repository" aktivieren.
  3. Namensschema — jsc-kapXX-klasse-nr verbindlich vorgeben: eindeutig, anonym, sortierbar.
  4. Erste Einheit — Schüler folgen der Schüler-Anleitung (oben). Du hilfst bei den ersten Clones.
  5. Übersicht — Suche in der Org: jsc-kap02 zeigt alle Abgaben. Für Fortgeschrittene: gh CLI (gh search repos).
  6. Feedback — Im Schüler-Repo: Issue oder Kommentar pro Commit. Kein Korrektur-Commit direkt auf main.
  7. Datenschutz-Kurzcheck — Private Repos; keine Klarnamen; keine Noten in Repos; Export der Reflexionen (.md) bleibt lokal.

Typische Fehler

„Schüler hat keinen Account"

Anmeldung mit Schülermail, GitHub Student Pack optional — in Minuten erledigt.

„Zu viele Einzel-Repos"

Namensschema + Org-Suche statt Dashboard — so behältst du auch bei 30 Repos den Überblick.

„Schüler pusht nicht"

Terminal-Triage: git status zeigt, was committet oder gepusht werden muss.

„Org-Grenzen"

Der Free-Plan reicht für private Repos im Unterrichtsmaßstab — keine Kosten, kein Upgrade nötig.
